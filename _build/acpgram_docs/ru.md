## Что такое AcpGram {#intro}

AcpGram — мост между Telegram и кодинг-агентами. Он устанавливается на ваш компьютер или сервер и запускает там агента: Claude Code, OpenAI Codex, Gemini CLI, Antigravity CLI или OpenCode. Вы пишете задачу боту в Telegram, агент читает файлы, запускает команды и правит код в выбранном проекте, а ход работы, запросы на подтверждение и результат приходят в чат.

AcpGram не заменяет агента и сам ничего не «думает». Это пульт: один бот с общим интерфейсом и командами, внутри которого вы переключаете агента, модель, проект и сессию.

Проект бесплатный, с открытым кодом (лицензия MIT). Вы платите только за самого агента — подписку или API его провайдера, как и при работе в терминале. С OpenCode можно начать совсем без оплаты: у него есть бесплатные модели, которым не нужен ключ.

### Как это устроено {#how-it-works}

1. **Telegram.** Вы пишете боту с телефона или компьютера.
2. **AcpGram.** Бот работает на вашей машине и сам подключается к Telegram. Публичный IP, открытые порты и облачный посредник не нужны.
3. **Агент.** AcpGram запускает агента как подпроцесс на той же машине и общается с ним по открытому протоколу [Agent Client Protocol](https://agentclientprotocol.com) (ACP).

Агент работает там, где установлен AcpGram. Пока эта машина выключена или спит, бот не ответит. После перезагрузки служба запустит бота сама.

Чтобы управлять несколькими машинами, создайте отдельного бота для каждой и установите AcpGram на каждой со своим токеном.

### Поддерживаемые агенты {#agents}

| Агент | Что нужно на машине | Авторизация |
|---|---|---|
| Claude Code | Claude Code и мост `claude-agent-acp` | вход в аккаунт или `ANTHROPIC_API_KEY` |
| OpenAI Codex | Codex CLI и мост `codex-acp` | `codex login` или `OPENAI_API_KEY` |
| Gemini CLI | только Gemini CLI | вход в аккаунт или `GEMINI_API_KEY` |
| Antigravity CLI | Antigravity CLI 1.5 или новее | вход через Google или ключ Gemini API |
| OpenCode | только OpenCode | бесплатные модели без ключа или ключи провайдеров |

Достаточно одного агента. Остальные можно подключить позже: AcpGram сам находит установленные.

### Требования {#requirements}

- Windows, Linux или macOS. Проверено на Windows Server и Linux (Ubuntu); на macOS используется тот же код, что и на Linux.
- Node.js. Установщик одной командой сам поставит приватный Node.js 24, если подходящего нет. Для установки через npm нужен Node.js 22.13 или новее, для запуска из исходников — Node.js 24.
- Для службы Windows — NSSM: установщик одной командой ставит его сам без прав администратора; при установке через npm — `winget install --id NSSM.NSSM -e`. Для запуска в консоли NSSM не нужен.
- Хотя бы один агент из таблицы выше.
- Бот в Telegram и его токен от [@BotFather](https://t.me/BotFather).
- Для раздела Git — установленный `git`. Для песочницы на Linux — пакет `bubblewrap`.

У самого AcpGram нет зависимостей npm.

## Установка {#install}

Обычно установка занимает несколько минут. Если агент у вас уже работает в терминале, понадобятся две-три команды.

### Шаг 1. Подготовьте агента {#install-agent}

Выберите агента, которым пользуетесь. Команды `npm` требуют Node.js с npm. Если на Windows `npm` отвечает, что выполнение сценариев отключено, см. [решение](#powershell-scripts).

**OpenCode** — самый простой старт: работает сразу на бесплатных моделях, без ключей и аккаунтов.

```sh
npm install -g opencode-ai
```

Этот шаг можно пропустить: если на машине нет ни одного агента, мастер настройки AcpGram сам предложит установить OpenCode.

**Claude Code.** Нужен сам Claude Code и мост, через который AcpGram с ним общается:

```sh
npm install -g @anthropic-ai/claude-code@latest
npm install -g @agentclientprotocol/claude-agent-acp
```

Запустите `claude` и войдите в аккаунт либо укажите ключ `ANTHROPIC_API_KEY` в мастере AcpGram. На Windows пригодится Git for Windows.

**OpenAI Codex.** Нужен Codex CLI и мост:

```sh
npm install -g @openai/codex
npm install -g @agentclientprotocol/codex-acp
codex login
```

Вместо `codex login` можно указать `OPENAI_API_KEY`. На Windows режимам «Чтение» и «Обычный» нужна рабочая песочница Codex; если команды падают с ошибкой `runner pipe-in`, используйте уровень «Полный».

**Gemini CLI.** Мост не нужен:

```sh
npm install -g @google/gemini-cli
```

Запустите `gemini` и авторизуйтесь либо укажите `GEMINI_API_KEY`.

**Antigravity CLI.** Нужна версия 1.5 или новее. Мост не нужен, достаточно один раз войти через Google:

```sh
agy acp --login
```

Вместо входа можно работать по ключу Gemini API: задайте `GEMINI_API_KEY` и добавьте `"modelProvider": "gemini"` в `settings.json` Antigravity (`~/.gemini/antigravity-cli/settings.json`).

### Шаг 2. Создайте бота в Telegram {#install-bot}

Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot` (или нажмите «Create a New Bot» в его окне), придумайте имя и скопируйте токен, который он пришлёт. Это занимает минуту.

Если хотите вести несколько задач параллельно, включите боту темы в настройках @BotFather: тогда каждая тема чата станет отдельным диалогом с агентом (см. [режим «Диалоги»](#topics)).

{{shot: botfather | Окно @BotFather с кнопкой «Create a New Bot»}}

### Шаг 3. Установите AcpGram {#install-acpgram}

**Одной командой (рекомендуется).** Windows, в PowerShell:

```powershell
irm https://raw.githubusercontent.com/selesnow/acpgram/main/install.ps1 | iex
```

Linux и macOS, в терминале:

```sh
curl -fsSL https://raw.githubusercontent.com/selesnow/acpgram/main/install.sh | bash
```

Установщик скачивает последний релиз с проверкой контрольной суммы в `%LOCALAPPDATA%\acpgram` (Windows) или `~/.local/share/acpgram` (Linux, macOS), при необходимости ставит приватный Node.js 24 и NSSM для службы Windows без прав администратора, добавляет команду `acpgram` в `PATH` и сразу запускает мастер настройки.

**Через npm.** Если Node.js 22.13 или новее уже установлен:

```sh
npm install -g acpgram
acpgram setup
```

> На Windows NSSM нужен только для службы. Установщик одной командой ставит его сам; при установке через npm: `winget install --id NSSM.NSSM -e`. Для запуска в консоли NSSM не нужен.

> На Windows PowerShell может ответить, что выполнение сценариев отключено в этой системе, и не запустить `npm` или `acpgram`. Как это исправить одной командой: [Windows: «выполнение сценариев отключено»](#powershell-scripts).

Настройки (`.env`) и база (`data/bot.db`) при такой установке лежат в `~/.acpgram` (или в папке из `ACPGRAM_HOME`) и не теряются при обновлении пакета.

### Шаг 4. Мастер настройки {#setup-wizard}

Мастер запускается сам после установки. Его можно запускать повторно командой `acpgram setup`: текущие значения подставляются.

1. **Токен бота.** Мастер сразу проверяет его в Telegram и показывает имя бота.
2. **Администратор.** Напишите своему боту любое сообщение — мастер сам определит ваш Telegram ID. Можно ввести ID вручную.
3. **Корень проектов** — необязательно. Если задать, мастер спросит и про [личные пространства](#workspaces).
4. **Песочница** — только на Linux и только если установлен `bubblewrap` (см. [песочницу агента](#sandbox)). Мастер также предлагает включить `ADMIN_SANDBOX=1`, чтобы изолировать агента администратора.
5. **Агенты.** Мастер находит установленные агенты, записывает их полные пути (чтобы они находились и под службой) и предлагает выбрать агента по умолчанию. Если не установлен ни один, предлагает сразу поставить OpenCode.
6. **Ключи API** — необязательно. Токен, ключи и пароль вводятся скрыто.
7. **Сохранение.** Мастер записывает `.env` (доступен только владельцу), создаёт базу и присылает вам тестовое сообщение в Telegram.
8. **Служба.** Мастер предлагает зарегистрировать бота как службу, чтобы он запускался вместе с системой.

{{shot: setup-wizard | Мастер настройки AcpGram в терминале}}

После этого откройте бота в Telegram и отправьте `/start`.

### Служба и автозапуск {#service}

Служба запускает бота вместе с системой и перезапускает при сбое. Обычно её ставит мастер, но ею можно управлять и вручную:

```sh
acpgram service install
acpgram service status
acpgram service restart
acpgram service stop
acpgram service uninstall
```

| ОС | Как работает служба |
|---|---|
| Windows | служба через [NSSM](https://nssm.cc): установщик AcpGram ставит его сам, при установке через npm — `winget install --id NSSM.NSSM -e`; терминал от имени администратора |
| Linux | `systemd --user`; чтобы бот работал без входа в систему, выполните `sudo loginctl enable-linger $USER` |
| macOS | LaunchAgent (`launchd`) |

На Windows службе нужен **пароль** вашей учётной записи: под ней авторизованы агенты. Если вы входите через учётную запись Microsoft, это пароль от неё, а не PIN-код Windows. Учётная запись без пароля службу запустить не может. Пароль не выводится на экран и ботом не сохраняется.

`acpgram service stop` останавливает службу, не удаляя её: после перезагрузки она запустится снова. Журнал службы — `data/service.log` в папке данных бота (на Linux ещё и `journalctl --user -u acpgram -f`).

### Обновление {#update}

Если ставили установщиком:

```sh
acpgram update
acpgram service restart
```

Если через npm:

```sh
npm install -g acpgram@latest
acpgram service restart
```

Настройки и история сессий сохраняются.

### Docker {#docker}

В образе уже есть все пять агентов и мосты: на хост ничего ставить не нужно, мастер тоже не нужен. Понадобятся Git и Docker с Docker Compose.

```sh
git clone https://github.com/selesnow/acpgram.git
cd acpgram
cp .env.example .env
```

Заполните в `.env` токен бота, свой Telegram ID, ключ агента и папку с проектами. Например, для Gemini CLI:

```sh
TELEGRAM_BOT_TOKEN=YOUR_BOT_TOKEN
ALLOWED_USER_ID=YOUR_TELEGRAM_ID
DEFAULT_ENGINE=gemini
GEMINI_API_KEY=YOUR_API_KEY
PROJECTS_DIR=./projects
```

```sh
docker compose up -d --build
docker compose logs -f
```

- `PROJECTS_DIR` — папка проектов на хосте. В контейнере она становится `/projects`: это и есть корень для `/project`. Агент видит только её.
- Авторизация по ключам из `.env`: Gemini — `GEMINI_API_KEY`, Claude Code — `ANTHROPIC_API_KEY`, Codex — `OPENAI_API_KEY`. OpenCode работает и без ключа, на бесплатных моделях.
- Antigravity CLI: после запуска один раз выполните `docker compose exec -it bot agy acp --login` либо работайте по ключу Gemini API.
- Чтобы собрать образ полегче, перечислите нужных агентов в `ENGINES` (`ENGINES=gemini claude`); `DEFAULT_ENGINE` должен быть из собранных.
- Бот в контейнере работает от пользователя `node` (uid 1000). Чтобы агент мог менять файлы, папка проектов должна быть доступна этому uid на запись: `sudo chown -R 1000:1000 <папка>`.
- Настройки, входы и история агентов хранятся в томах и переживают обновление контейнера. `docker compose down -v` их удаляет.
- Нужны R, Python или другие инструменты — сделайте свой `Dockerfile` поверх образа.

Docker или установка напрямую? Напрямую агент получает всё, что установлено на машине, и работает с правами учётной записи бота. В Docker он изолирован от системы и видит только папку проектов, но и инструменты у него только те, что есть в образе. [Песочница агента](#sandbox) в Docker не поддерживается.

### Запуск из исходников {#from-source}

Нужны Git и Node.js 24 или новее.

```sh
git clone https://github.com/selesnow/acpgram.git
cd acpgram
npm run setup
```

Если отказались от службы, бот запускается командой `npm start`. Первый запуск без `.env` сам откроет мастер настройки. Можно обойтись и без мастера: скопируйте `.env.example` в `.env`, заполните и запустите `npm start`.

### Переход с установщика на npm {#migrate-npm}

Установщик на Windows добавляет в `PATH` папку `%LOCALAPPDATA%\acpgram\bin`. Если после этого поставить AcpGram через npm, Windows может продолжать вызывать старую версию.

1. Остановите и удалите прежнюю службу: `acpgram service uninstall`. Иначе токен будет занят, и Telegram вернёт ошибку `Conflict`.
2. Проверьте, какая команда вызывается: `Get-Command acpgram`.
3. Уберите старую папку из пользовательского `PATH`:

```powershell
[Environment]::SetEnvironmentVariable("Path", (([Environment]::GetEnvironmentVariable("Path", "User") -split ';') | Where-Object { $_ -notlike '*\acpgram\bin' }) -join ';', "User")
```

4. Откройте новое окно терминала и запустите `acpgram setup`: мастер найдёт прежнюю установку и предложит перенести `.env` и базу.

## Первые шаги в боте {#first-steps}

### Экран /start {#start-screen}

Команда `/start` показывает, с чем вы сейчас работаете: агент, модель, уровень доступа и проект. Под сообщением — кнопки основных действий, ниже — список команд.

{{shot: start | Экран /start: агент, модель, уровень доступа, проект и кнопки действий}}

Кнопки повторяют команды: проект, новая сессия, прошлые сессии, агент, модель, завершение сессии, файлы, Git, язык, режим диалогов. У администратора есть ещё сотрудники, приглашение и активные сессии.

### Как поставить задачу {#first-task}

1. Выберите проект: `/project` (см. [Проекты](#projects)).
2. Напишите задачу обычным сообщением, как коллеге: «найди, почему падает тест авторизации, и исправь».
3. Следите за ходом работы и отвечайте на запросы разрешений кнопками.
4. Получите ответ и, если нужно, файлы.

К сообщению можно приложить скриншот, документ или архив: подпись становится запросом (см. [Файлы](#files)).

### Ход работы и ответ {#progress}

Пока агент работает, бот показывает черновик сообщения:

- пока агент запускается — анимированные точки Telegram;
- затем заголовок размышлений и ход работы: последние пять шагов, счётчик остальных и время выполнения;
- если агент прислал боту свой план — блок «План: 3/7» с пунктами (см. [План работы](#plan));
- как только пошёл ответ — последний шаг и сам текст ответа.

### План работы {#plan}

Некоторые агенты ведут список дел и присылают его боту. Тогда в черновике появляется блок «План: 3/7» с пунктами и отметками: ✅ сделано, ▶️ выполняется, ▫️ впереди. Блок виден, только пока агент работает: когда приходит ответ, он исчезает вместе с черновиком.

Так бывает не всегда, и зависит это от агента, а не от бота:

- **OpenCode** план боту не присылает. Список дел он ведёт, но в ходе работы это выглядит как обычный шаг «План работы».
- **Claude Code и Codex** присылать план умеют, но пользуются этим не в каждой задаче: часто агент просто пишет список текстом в ответе.
- **Gemini CLI и Antigravity CLI:** показ плана не подтверждён.

Если блока «План» нет, план всё равно можно получить: попросите агента сначала составить список дел и отмечать пункты по ходу работы. Он напишет его текстом, как на снимке ниже.

{{shot: plan-text | Агент без блока «План»: список дел из шести пунктов написан текстом в ответе}}

**Режим планирования Claude Code.** У Claude Code есть собственный режим планирования: агент сначала составляет план, сохраняет его в файл и просит одобрить. Бот показывает этот запрос с вариантами самого Claude Code (они приходят на английском): одобрить и подтверждать правки вручную, одобрить и работать без подтверждений, одобрить и перейти в автоматический режим либо отклонить. Варианты, которые дали бы агенту больше свободы, чем разрешает ваш уровень доступа, бот не показывает.

{{shot: plan-approve | Запрос Claude Code на одобрение плана: варианты продолжения работы и кнопка отклонения}}

В самом запросе текста плана нет. Если хотите прочитать план до одобрения, попросите агента сначала прислать его в чат.

### Запросы разрешений {#permissions}

Когда агенту нужно разрешение на команду или правку файла, бот присылает запрос с кнопками:

- **«Разрешить»** — только это действие;
- **«Разрешить на эту сессию»** — это и такие же действия до конца сессии;
- **«Отклонить»**.

Команда показывается блоком кода, а в запросе на правку файла виден дифф: что именно агент изменит, а не только путь.

{{shot: permission | Запрос разрешения на команду: команда блоком кода и кнопки «Разрешить», «На эту сессию: только эта команда», «Отклонить»}}

{{shot: permission-diff | Запрос разрешения на правку файла с диффом; ниже — отметка, что правка разрешена на эту сессию}}

Как работает «на эту сессию»:

- на кнопке написано, что именно будет разрешено;
- правки файлов разрешаются целиком;
- команды — по имени программы: разрешили `ls` — без вопросов пойдут все `ls …`;
- у программ с подкомандами (`git`, `npm`, `docker` и подобных) — по программе и подкоманде: разрешили `git status` — пойдут все `git status …`, но не `git push`;
- оболочки (`bash -c`, `powershell`, `cmd /c`, `sudo`), интерпретаторы (`python`, `node`, `Rscript`, `npx`), команды с подстановками, записью в файл и переменными перед программой разрешаются только точно такие же;
- в составной команде должны быть разрешены все части.

Длинная команда показывается началом и концом с пометкой об обрезке; строки журнала тоже обрезаются.

Правило живёт, пока работает процесс агента: до `/new`, `/close`, закрытия по простою или перезапуска бота. Варианта «разрешить навсегда» в чате нет.

Будут ли вообще приходить запросы, зависит от [уровня доступа](#access-levels).

### Кнопки быстрого ответа {#quick-replies}

Когда агент предлагает выбор («Какой вариант применить?»), варианты приходят кнопками прямо в его ответе. Нажатие отправляет текст варианта агенту как ваше сообщение.

{{shot: quick-reply | Вопрос агента с кнопками быстрого ответа}}

### Сообщение во время работы {#queue}

Сообщение, отправленное, пока агент выполняет запрос, не теряется. Бот ставит его в очередь и отправит агенту, как только тот закончит. Под уведомлением две кнопки: «Остановить и отправить это» и «Не отправлять». В очереди одно сообщение: новое заменяет прежнее.

{{shot: queue | Уведомление об очереди с кнопками «Остановить и отправить это» и «Не отправлять»}}

### Ответ с цитатой {#quotes}

Ответьте на сообщение агента, выделив в нём фрагмент: агент получит и ваш текст, и этот фрагмент. Удобно для просьб вроде «перепиши вот это».

### Остановка запроса {#stop}

Команда `/stop` или кнопка остановки под черновиком прерывает выполняющийся запрос, а если агент не ответил на отмену — завершает его процесс. Сессия при этом остаётся: можно сразу написать следующее сообщение.

Опечатка в команде (`/modle`) агенту не уходит: бот спросит, не имели ли вы в виду `/model`. На голосовое, видео и стикер бот отвечает подсказкой.

## Проекты {#projects}

Проект — это папка, в которой работает агент. Выбор запоминается для каждого пользователя.

### Выбор проекта {#project-select}

Команда `/project` показывает папки кнопками. Вверху — последние проекты, по папкам можно ходить, а нужную выбрать кнопкой «Выбрать эту папку».

{{shot: project | Экран /project: папки корня проектов и кнопки выбора папки, нового проекта и клонирования из Git}}

Быстрее — указать название или путь:

```text
/project landing
/project C:\my-app
/project ~/projects/web
```

Что доступно для выбора, зависит от настроек:

- без `PROJECTS_ROOT` (личная установка) — любая существующая папка, по умолчанию домашняя;
- с `PROJECTS_ROOT` — только папки внутри корня;
- с `PROJECTS_ROOT` и `USER_WORKSPACES=1` — у каждого сотрудника своя папка внутри корня (см. [личные пространства](#workspaces)).

### Новый проект {#project-new}

Кнопка «➕ Новый проект» в `/project` спрашивает название, создаёт папку в открытом месте и сразу делает её рабочей. Неподходящее название (путь, служебное имя, точка в начале) бот попросит заменить. «Отмена» или любая команда отменяют ожидание.

Администратору кнопка доступна везде, сотруднику — в его личном пространстве.

### Проект из репозитория {#project-clone}

Кнопка «⬇️ Из Git» в `/project` показывает ваши репозитории на подключённых сервисах списком с поиском. Выбранный репозиторий клонируется и сразу становится проектом. Сначала нужно подключить аккаунт в `/git` (см. [Git](#git)).

## Сессии и диалоги {#sessions}

Сессия — это один разговор с агентом: он помнит всё, о чём шла речь.

### Новая сессия и возврат к прошлой {#sessions-resume}

- `/new` начинает новую сессию: агент забывает предыдущий разговор.
- `/sessions` показывает прошлые сессии текущего проекта: дата, агент, число запросов и начало первого запроса. Нажатие возобновляет сессию с того же места, даже после перезапуска бота.

Сессия возобновляется в том агенте, в котором была создана. Смена агента командой `/engine` начинает новую сессию.

{{shot: sessions | Экран /sessions: список прошлых сессий проекта с датой, агентом и началом запроса}}

### Режим «Диалоги»: темы Telegram {#topics}

Если боту включены темы в личном чате (в настройках @BotFather), каждая тема чата становится отдельным диалогом с агентом: со своим проектом, агентом и историей.

- Можно работать в нескольких темах одновременно.
- Вернувшись в тему позже, вы продолжаете с того же места: сессия возобновляется сама.
- `/new` создаёт новую тему. Название ей даёт агент по первому ответу, с коротким именем проекта в начале.
- Тема закреплена за своим проектом.
- General работает как обычный диалог, а `/project` в нём показывает диалоги выбранного проекта кнопками.

{{shot: topics | Чат с ботом в режиме «Диалоги»: слева список тем, каждая тема — отдельный диалог с агентом}}

Режим каждый выбирает сам командой `/topics`: «Диалоги» или «Один чат».

Одновременно у сотрудника работает до двух агентов, у администратора — до четырёх (настройки `MAX_AGENTS_PER_USER` и `ADMIN_MAX_AGENTS`). Если места нет, выгружается самый давний простаивающий агент этого же пользователя; его диалог продолжится, когда вы в него вернётесь.

### Закрытие сессии {#sessions-close}

`/close` (или `/exit`) закрывает сессию и выгружает процесс агента. Простаивающая сессия закрывается сама через 30 минут (`IDLE_MINUTES`). Закрытую сессию можно возобновить через `/sessions`.

## Агенты и модели {#engines-models}

### Выбор агента {#engine}

В интерфейсе бота агент называется «движок»: кнопка «🤖 Движок» и команда `/engine`.

Команда `/engine` показывает агентов, доступных вам на этой машине. Выбор запоминается для каждого пользователя, смена агента начинает новую сессию.

```text
/engine claude
/engine opencode
```

Агенты, которых нет на сервере, не предлагаются. Агент, который запускается, но не авторизован (нет входа или ключа API), помечен «⚠️ нужен вход». Агент по умолчанию задаётся настройкой `DEFAULT_ENGINE`.

{{shot: engine | Экран /engine: список доступных агентов, текущий выделен}}

### Выбор модели {#model}

Команда `/model` показывает модели текущего агента (список присылает сам агент) и уровень рассуждений, где он есть: у Claude Code и Antigravity CLI.

- По умолчанию стоит «Авто»: модель выбирает сам агент.
- Выбор запоминается отдельно для каждого агента и применяется со следующего запроса, без перезапуска сессии.
- Вверху экрана — кнопки с последними выбранными моделями.
- Самый быстрый способ — поиск: `/model sonnet` покажет все подходящие модели кнопками.

{{shot: model | Экран /model у OpenCode: бесплатные модели, текущая отмечена галочкой}}

### OpenCode и бесплатные модели {#opencode}

OpenCode берёт модели тех провайдеров, чьи ключи есть в `.env` бота или подключены командой `opencode auth login`, плюс бесплатные модели, которым ключ не нужен.

- Каждый ключ добавляет группу моделей в `/model`: Anthropic, OpenAI, Gemini, OpenRouter, Groq, DeepSeek, Mistral и другие провайдеры OpenCode.
- OpenRouter даёт сотни моделей разных разработчиков по одному ключу.
- Моделей много, поэтому сначала выбирается группа («🆓 Бесплатные» или провайдер), а внутри неё модели листаются страницами. У агрегаторов внутри группы есть ещё и разработчики моделей.
- Модели, которые не умеют вызывать инструменты (генерация картинок, музыки), не показываются.
- После добавления нового ключа список моделей обновляется сам: при перезапуске бота или при следующем `/model`.

> Бесплатные модели могут использовать запросы для обучения. Не отправляйте в них секреты и закрытый код. Ключи и пароли передавайте проекту через [/files](#files-project).

## Файлы {#files}

### Файлы для агента {#files-to-agent}

Фото или файл (текст, PDF, таблица и так далее, до 20 МБ) можно отправить боту: подпись становится запросом. Файл сохраняется на машине с ботом, агент получает путь к нему и читает его своими инструментами. Изображения агент получает ещё и как картинку, если умеет с ними работать.

- Альбом из нескольких фото или файлов обрабатывается одним запросом.
- Архивы `.zip`, `.tar`, `.tar.gz`, `.tgz` бот распаковывает сам (не больше 500 файлов и 100 МБ) и передаёт агенту список файлов. `.7z` и `.rar` остаются обычным файлом.
- Присланные файлы хранятся 7 дней (`FILES_KEEP_DAYS`).
- Загрузки обрабатываются по очереди: если агент занят, лишний файл удаляется, а вы получаете сообщение «занято».
- Место под загрузки можно ограничить настройкой `UPLOADS_QUOTA_MB`.

### Файлы от агента {#files-from-agent}

Агент может создать файл и прислать его в чат: отчёт, таблицу, картинку, архив. Просто попросите: «пришли результат файлом». Файл появляется прямо в ответе: JPEG и PNG — изображением, остальное — документом.

{{shot: files-from-agent | Ответ агента с изображением, которое он создал и прислал в чат}}

Отправляются только файлы из папки проекта и из каталога исходящих файлов бота. Файлы с секретами (`.env`, ключи, база и журналы бота, папка `.git`) в чат не отправляются.

### Файлы проекта и секреты: /files {#files-project}

Всё, что вы пишете боту или отправляете ему файлом, уходит агенту, а значит, в запрос к модели. Для паролей, токенов и ключей это не подходит. Команда `/files` кладёт файл прямо в папку проекта, минуя агента.

{{shot: files | Экран /files: файлы и папки проекта, кнопки «Создать файл» и «Загрузить файл»}}

- **Список.** `/files` показывает файлы и папки текущего проекта, вместе со скрытыми вроде `.env` (без `.git`, `node_modules` и ссылок). По папкам можно ходить кнопками, у файла есть карточка с размером и датой изменения.
- **«📝 Создать файл».** Бот спрашивает имя, можно с подпапкой: `config/.env`. Затем вы присылаете содержимое одним сообщением (до 3500 символов). Сообщение с содержимым сразу удаляется из чата; в базу и журналы оно не пишется.
- **«⬆️ Загрузить файл».** Следующий присланный файл или альбом сохраняется в открытую папку проекта под своим именем, а сообщение с ним удаляется из чата. Ожидание одноразовое и истекает через 10 минут.
- **Удаление** — из карточки файла, с подтверждением. Существующий файл заменяется только после вопроса «Заменить?».

Ожидание ввода секрета хранится в базе: после перезапуска бота старое сообщение с токеном не будет принято — нужно нажать кнопку заново.

{{shot: files-create | Создание файла через /files: запрос имени и сообщение о сохранении}}

Без нажатия кнопки всё работает как раньше: файлы и изображения, отправленные в чат, уходят агенту.

На уровне «Чтение» папки настроек агентов (`.claude`, `.gemini`, `.codex`, `.opencode`, `opencode.json`) в `/files` не показываются; обычные файлы, `.env` и клонирование остаются доступными прежним образом.

Кто может менять файлы: администратор; сотрудник — в своём личном пространстве, а в общем корне — с уровнем «Обычный» или «Полный». Смотреть список может любой. Бот не пишет и не удаляет за пределами папки проекта и не ходит по ссылкам.

> Что это даёт и чего не даёт. Секрет не попадает в запрос к модели от вас. Сам файл агенту доступен, иначе приложения, которые он пишет и запускает, не смогли бы им пользоваться. Бот регулярно напоминает агенту: файлы с секретами не открывать и не выводить, на настройки ссылаться по именам, а за недостающим значением отправлять вас в `/files`. Это указание, а не запрет: для особо чувствительных данных выбирайте модель провайдера, который не обучается на запросах.

## Git: GitHub и GitLab {#git}

Команда `/git` связывает проекты с GitHub, GitLab.com и своими серверами GitLab и GitHub Enterprise. Подключить аккаунт, клонировать репозиторий, посмотреть изменения, отправить код и открыть запрос на слияние можно кнопками, не открывая терминал.

{{shot: git | Экран /git: подключённые аккаунты, кнопки публикации проекта и клонирования}}

### Что нужно {#git-requirements}

На машине с ботом должен быть установлен `git`. Это системная программа, а не зависимость бота; без неё раздел отвечает, что недоступен. Если `git` не в `PATH`, укажите путь в настройке `GIT_COMMAND`.

### Вход без токена {#git-signin}

GitHub и GitLab.com подключаются по ссылке и короткому коду:

1. `/git` → «➕ Подключить GitHub» или «➕ Подключить GitLab.com».
2. Нажмите «🔗 Войти без токена». Бот покажет ссылку и код.
3. Откройте ссылку, введите код и подтвердите доступ на сайте сервиса.
4. Через несколько секунд бот сам напишет, что аккаунт подключён.

{{shot: git-signin | Вход без токена: сообщение бота со ссылкой и кодом}}

Создавать токен и присылать что-то секретное в чат не нужно. Это работает в любой установке без настройки.

У GitLab такой вход действует два часа, и бот сам продлевает его перед каждой операцией. Если сервис перестал принимать вход, аккаунт отключается, и бот просит подключить его заново. У GitHub вход бессрочный, пока вы не отключите аккаунт или не отзовёте доступ в настройках GitHub.

### Вход по токену доступа {#git-token}

Нажмите «➕ Подключить …»: бот даст ссылку на страницу токенов сервиса и список нужных прав. Создайте токен и пришлите его одним сообщением.

- Сообщение с токеном сразу удаляется из чата и агенту не передаётся.
- Бот проверяет токен в сервисе, показывает, кто подключён и до какого числа токен действует, и предупреждает, если прав не хватает.
- Нужные права: у GitLab — `api`, `read_repository`, `write_repository` (без `api` не работают публикация и запросы на слияние), у GitHub — `repo`.
- За неделю, за день и по истечении срока токена бот напишет владельцу аккаунта.
- Отключение аккаунта в его карточке удаляет токен из бота.

### Свои серверы {#git-servers}

GitLab и GitHub Enterprise вашей компании добавляет администратор прямо в боте: `/git` → «⚙️ Свои серверы» → «➕ GitLab» или «➕ GitHub Enterprise» → адрес сервера, например `https://git.example.com`.

Бот проверяет, что по адресу отвечает сервер нужного вида. После этого каждый пользователь может подключить на нём свой аккаунт токеном доступа. Там же сервер переименовывается и убирается — вместе с подключёнными к нему аккаунтами.

{{shot: git-servers | Экран «Свои серверы»: добавление GitLab или GitHub Enterprise}}

Вход по ссылке и коду работает только для GitHub.com и GitLab.com. Свои серверы подключаются токеном.

### Клонирование {#git-clone}

«⬇️ Клонировать репозиторий» (или «⬇️ Из Git» в `/project`) показывает ваши репозитории кнопками: недавно менявшиеся первыми, с поиском по названию. Выбранный клонируется в личное пространство (без него — рядом с текущим проектом) и становится проектом.

{{shot: git-clone | Список репозиториев для клонирования: кнопки репозиториев, переход по страницам и поиск}}

### Экран репозитория {#git-repo}

Когда проект связан с репозиторием, `/git` показывает ветку, число изменённых файлов, неотправленных коммитов и новых коммитов на сервере. При открытии и по кнопке «Обновить» экран сверяется с сервером.

{{shot: git-repo | Экран репозитория: ветка, изменённые файлы, неотправленные коммиты и кнопки действий}}

- **«⬇️ Получить»** забирает изменения с сервера, если это возможно без слияния. Если истории разошлись, попросите агента объединить изменения («объедини изменения с сервера») и затем отправьте.
- **«⬆️ Отправить»** отправляет готовые коммиты.
- **«💾 Сохранить и отправить»** спрашивает описание, коммитит все изменения и отправляет.

Автор коммитов — владелец подключённого аккаунта: его имя и почта передаются и боту, и агенту, так что коммиты агента подписаны вами.

### Изменения и дифф {#git-changes}

«📋 Изменения» открывает список изменённых файлов с пометками (новый, изменён, удалён, переименован) и числом добавленных и убранных строк. Нажатие на файл показывает, что в нём изменилось: короткие изменения — прямо в сообщении, длинные — файлом.

{{shot: git-changes | Список изменённых файлов с числом добавленных и убранных строк}}

{{shot: git-diff | Дифф файла в сообщении бота}}

Там же — коммиты, которые ещё не отправлены, и те, что ждут на сервере. Содержимое файлов с секретами не показывается. Всё это бот делает сам, без агента и без запросов к модели.

### Ветки {#git-branches}

«🌿 Ветки» показывает локальные ветки и ветки сервера одним списком. Нажатие переключает на ветку, «➕ Новая ветка» создаёт её от текущей.

{{shot: git-branches | Список веток: текущая отмечена, кнопка «Новая ветка»}}

- При несохранённых изменениях бот не переключает, а предлагает сначала сохранить их.
- Пока агент выполняет запрос, переключение недоступно.
- После переключения следующий запрос начинает новую сессию агента: файлы проекта сменились.
- «Отправить» создаёт новую ветку и на сервере.

Смотреть изменения и ветки может любой пользователь; переключать и создавать ветки — тот, кому разрешено менять файлы проекта.

### Отмена изменений {#git-discard}

В карточке изменённого файла есть «↩️ Вернуть как было», на экране «Изменения» — «↩️ Отменить все изменения». Изменённые и удалённые файлы возвращаются к последнему коммиту, новые удаляются.

Действие необратимо, поэтому бот всегда просит подтверждение. Файлы с секретами не затрагиваются.

### Публикация проекта {#git-publish}

Для папки, которая ещё не связана с сервером, есть «🚀 Опубликовать проект». Вы выбираете:

### Когда отправку предлагает агент {#git-agent}

По умолчанию у агента нет входа на сервер. Поэтому просьбу «закоммить и отправь» он выполняет так: делает коммит, а под его ответом появляется кнопка отправки. Без вашего нажатия на сервер ничего не уходит.

{{shot: git-offer | Ответ агента с кнопкой отправки изменений на сервер}}

### Где хранится вход и как запускается git {#git-security}

По умолчанию вход хранится только в базе бота. Клонирование, получение и отправку делает бот, а агент работает с репозиторием локально: смотрит состояние, сравнивает, коммитит, создаёт ветки, сливает.

- Вход передаётся процессу `git` через окружение на время операции и только для адресов своего сервиса. В настройки репозитория и в адрес он не пишется.
- Бот запускает `git` с отключёнными хуками и помощниками входа, без общего и системного конфига (на Linux и macOS), а при включённой песочнице — внутри песочницы того же сотрудника.
- При «Сохранить и отправить» файлы с секретами (`.env`, ключи, учётные данные) из коммита исключаются и дописываются в `.gitignore`. Если такой файл закоммитил агент, перед отправкой бот предупреждает и ждёт «Отправить всё равно».

Администратор может выбрать другой режим: `GIT_AGENT_AUTH=1`. Тогда вход передаётся и процессу агента, и он сам получает и отправляет изменения. Это удобнее, но токен становится виден агенту и может попасть в запрос к модели. Включайте этот режим, только если доверяете моделям, с которыми работают сотрудники.

### Ограничения {#git-limits}

- Подключаются только репозитории по HTTPS с подключённых сервисов. Репозиторий с адресом SSH или с другого сервера бот показывает, но получать и отправлять в него не может.
- Пока агент выполняет запрос, операции Git не запускаются.
- Настройки самого репозитория (фильтры) выполняются при операциях: намеренно вредоносный агент мог бы перехватить токен во время операции.

## Работа в команде {#team}

AcpGram можно поставить на общий сервер и выдать доступ коллегам, в том числе тем, кто не работает в терминале: всё управление идёт из Telegram.

### Как добавить человека {#team-invite}

По умолчанию бот отвечает только главному администратору (настройка `ALLOWED_USER_ID`). Остальных добавляют двумя способами:

- **Приглашение.** `/invite` спрашивает уровень доступа и создаёт одноразовую ссылку, которая действует 24 часа.
- **Запрос доступа.** Человек пишет боту, администратор получает запрос и одобряет или отклоняет его кнопками. Запрос отправляется не чаще раза в час; отклонённых бот игнорирует.

Команда `/users` показывает список сотрудников. В карточке сотрудника: уровень доступа, доступные агенты и модели, завершение сессии и отзыв доступа.

{{shot: users | Экран /users: список сотрудников с уровнем доступа}}

### Уровни доступа {#access-levels}

| Уровень | Что это значит |
|---|---|
| Чтение | агент только читает и анализирует, ничего не меняет |
| Обычный | агент спрашивает разрешение на правки и команды; запросы приходят самому сотруднику |
| Полный | агент работает с минимумом подтверждений или совсем без них (зависит от агента) |
| Администратор | полный доступ и управление сотрудниками |

Каждый уровень соответствует своему режиму у каждого агента:

| Уровень | Gemini CLI | Claude Code | Antigravity CLI | Codex | OpenCode |
|---|---|---|---|---|---|
| Чтение | `plan` | `plan` | `plan` | `read-only` | `plan` |
| Обычный | `default` | `default` | `default` | `workspace-write` | `build` |
| Полный | `autoEdit` | `bypassPermissions` | `accept-edits` | `agent-full-access` | `build` |
| Администратор | `autoEdit` | `bypassPermissions` | `accept-edits` | `agent-full-access` | `build` |

На уровне «Полный» Gemini CLI и Antigravity CLI правят файлы без подтверждений, а команды выполняют с подтверждением; Claude Code работает вообще без подтверждений. У OpenCode режимов два, а что агенту можно, задаёт бот: «Чтение» — правки и команды запрещены, «Обычный» — правки, команды и загрузка страниц с подтверждением, «Полный» — всё без подтверждений.

Режим администратора можно изменить в `.env`: `ACP_MODE`, `CLAUDE_ADMIN_MODE`, `AGY_ADMIN_MODE`, `CODEX_ADMIN_MODE`, `OPENCODE_ADMIN_MODE`.

> Уровень «Полный» выдавайте только тем, кому доверяете. Без [песочницы](#sandbox) агент работает с правами учётной записи бота и может менять файлы за пределами проекта.

### Агенты и модели сотрудника {#team-engines}

- **Агенты.** Новому сотруднику доступен только агент по умолчанию, остальных администратор включает переключателями в его карточке. Агента по умолчанию отключить нельзя. Если забрать агента, в котором сотрудник работает, его сессия закрывается, и он переходит на агента по умолчанию.
- **Модели.** «🧠 Модели сотрудника» → агент → переключатели моделей. По умолчанию разрешены все. При ограничении вариант «Авто» недоступен: сотрудник работает в выбранной разрешённой модели или в первой из разрешённых. Если агент фактически использовал модель вне списка, запрос останавливается, а сессия закрывается с понятным сообщением.
- Администратору доступны все агенты и модели.

### Личные пространства {#workspaces}

По умолчанию все сотрудники ходят по одному корню проектов. Личные пространства дают каждому свою папку:

```sh
PROJECTS_ROOT=/srv/projects
USER_WORKSPACES=1
```

Папка `<корень>/<Telegram ID>` создаётся сама при первом обращении сотрудника к боту.

- Сотрудник выбирает проекты только в своей папке: чужие папки не показываются в `/project`, не находятся поиском и не выбираются путём. Подняться выше своей папки нельзя.
- Пути он видит от своей папки («Моё пространство», `site`, `site/landing`): расположение папок на сервере ему не показывается.
- Кнопка «➕ Новый проект» создаёт папку в его пространстве.
- Администратор видит весь корень; личные папки подписаны именами сотрудников, а папка сотрудника указана в его карточке в `/users`.
- Перед каждым запуском агента бот проверяет, что папка проекта существует и лежит в пространстве сотрудника.
- Папки сотрудников бот не переносит и не удаляет, в том числе при отзыве доступа.

Личные пространства ограничивают выбор рабочей папки в боте. Сам процесс агента изолирует песочница.

### Песочница агента (Linux) {#sandbox}

Без песочницы агент работает с правами учётной записи бота: рабочая папка задаёт, где он начинает, но не запрещает читать и писать за её пределами. Песочница закрывает этот вопрос.

```sh
sudo apt install bubblewrap
```

```sh
AGENT_SANDBOX=bwrap
```

Агент каждого сотрудника запускается через [bubblewrap](https://github.com/containers/bubblewrap), системную утилиту Linux. Зависимостей у бота не прибавляется.

Внутри песочницы агент видит только:

- на запись — папку проектов сотрудника, его отдельную домашнюю папку и каталог исходящих файлов;
- на чтение — его загруженные файлы, систему (`/usr`, `/etc` и подобное), Node.js и программы агента.

Настроек и базы бота, домашней папки учётной записи бота, чужих папок и чужих процессов в песочнице нет: на попытку прочитать чужой файл агент получает «No such file or directory».

Что ещё важно:

- **У каждого свои настройки агента.** Домашняя папка у сотрудника своя, поэтому история сессий, настройки и входы агентов у всех раздельные.
- **Агент должен работать без входа по подписке.** Вход, сохранённый в домашней папке учётной записи бота (`codex login`, вход Google, подписка Claude), в песочнице не виден. OpenCode на бесплатных моделях работает вообще без ключей, остальные агенты — по ключу API из `.env`.
- **Уровень «Полный» становится безопаснее.** Агент не спрашивает разрешений, но изменить может только пространство своего сотрудника.
- **Администратор работает без песочницы**, если не включён `ADMIN_SANDBOX=1`. С этой настройкой его агент тоже изолируется в папках внутри `PROJECTS_ROOT`: сотрудник не сможет оставить в общей папке файл настроек агента, который выполнится с правами бота. Бот один раз предупреждает администратора в чате, если песочница выключена, администратор работает без неё в общей папке или `.env` доступен локальным группам пользователей Windows.
- **Проверка при запуске.** Бот проверяет, что bubblewrap запускается, секреты бота изнутри не видны, а агенты в песочнице стартуют. Не работает песочница или агент по умолчанию — бот не запускается и пишет причину. Остальные агенты, не запустившиеся в песочнице, сотрудникам не предлагаются. Без `PROJECTS_ROOT` бот с `AGENT_SANDBOX=bwrap` не запускается; папки данных бота и других сотрудников в песочницу не подключаются.
- **Агент установлен в нестандартном месте** — добавьте его папку в `SANDBOX_RO_PATHS`.
- **Сессии, начатые до включения песочницы,** в ней не возобновляются.
- **Windows, macOS, Docker.** Песочницы там нет. С настройкой `AGENT_SANDBOX` бот на Windows и macOS не запустится, а не будет работать молча без изоляции.

Ubuntu 24.04 и новее: пространства имён пользователя могут быть закрыты AppArmor. Если бот при запуске сообщает, что песочница не работает, выполните:

```sh
sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
```

Для постоянства добавьте эту настройку файлом в `/etc/sysctl.d/` либо создайте профиль AppArmor для `bwrap`.

> Чего песочница не делает. Она не ограничивает сеть: агенту нужен доступ к моделям, поэтому он достаёт и до служб на самом сервере и в локальной сети. Она не прячет ключ API самого агента: он передаётся агенту в окружении, поэтому ставьте на ключ лимит расхода у провайдера. И она не ограничивает диск, память и процессор.

## Язык интерфейса {#language}

Бот говорит на русском, украинском или английском — по языку вашего Telegram. Для остальных языков используется `DEFAULT_LANG` (по умолчанию английский). Сменить язык можно командой `/language`: выбор важнее языка Telegram.

Команды `acpgram` в терминале (мастер настройки, служба, обновление) говорят на языке системы: русский, украинский, в остальных случаях английский. Язык можно задать настройкой `ACPGRAM_LANG`.

## Настройки: файл .env {#env}

Все настройки лежат в файле `.env` в папке данных бота: `~/.acpgram` при установке через npm, `%LOCALAPPDATA%\acpgram` или `~/.local/share/acpgram` при установке установщиком, корень репозитория при запуске из исходников. Большинство значений записывает мастер (`acpgram setup`). После правки файла вручную перезапустите службу: `acpgram service restart`.

Файл `.env` содержит токен и ключи: не коммитьте его и не пересылайте.

### Основные {#env-main}

| Переменная | Описание |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота. Обязательна |
| `ALLOWED_USER_ID` | числовой Telegram ID главного администратора. Обязательна |
| `DEFAULT_ENGINE` | агент по умолчанию: `gemini`, `claude`, `agy`, `codex` или `opencode`. Если он не установлен, бот не запускается |
| `DEFAULT_LANG` | язык бота, если язык Telegram пользователя не русский, украинский или английский: `en` (по умолчанию), `ru` или `uk` |
| `ACPGRAM_LANG` | язык команд `acpgram` в терминале: `ru`, `uk` или `en`. Обычно не нужна: язык берётся из системы |
| `ACPGRAM_HOME` | папка данных при установке через npm (по умолчанию `~/.acpgram`) |

### Агенты и ключи {#env-engines}

| Переменная | Описание |
|---|---|
| `GEMINI_API_KEY` | ключ Gemini API. Не нужен, если Gemini CLI уже авторизован |
| `ANTHROPIC_API_KEY` | ключ Anthropic API для Claude Code (оплата по API, а не по подписке) |
| `OPENAI_API_KEY` | ключ OpenAI API для Codex и моделей OpenAI в OpenCode |
| `OPENROUTER_API_KEY`, `GROQ_API_KEY`, `DEEPSEEK_API_KEY`, `MISTRAL_API_KEY` | ключи провайдеров для OpenCode: каждый добавляет группу моделей в `/model`. Подходят и другие провайдеры OpenCode со своими переменными |
| `GEMINI_COMMAND` | полный путь к Gemini CLI. Под службой глобальные пакеты npm часто не в `PATH` |
| `CLAUDE_COMMAND` | команда моста Claude Code (по умолчанию `claude-agent-acp`) |
| `CODEX_COMMAND` | полный путь к мосту Codex (по умолчанию `codex-acp`) |
| `AGY_COMMAND` | полный путь к Antigravity CLI (по умолчанию `agy`) |
| `OPENCODE_COMMAND` | полный путь к OpenCode (по умолчанию `opencode`) |
| `ACP_MODE`, `CLAUDE_ADMIN_MODE`, `AGY_ADMIN_MODE`, `CODEX_ADMIN_MODE`, `OPENCODE_ADMIN_MODE` | режим каждого агента для администратора (см. [уровни доступа](#access-levels)) |
| `AGENT_ENV_HIDE`, `AGENT_ENV_PASS` | дополнительные переменные окружения, которые соответственно скрыть от агента или передать ему (списки через запятую) |
| `AGENT_START_TIMEOUT` | сколько секунд ждать запуска агента (по умолчанию 120) |

Процесс агента получает из ключей API только ключи своего агента: Claude Code — `ANTHROPIC_API_KEY`, Codex — `OPENAI_API_KEY`, Gemini CLI и Antigravity CLI — ключи Google, OpenCode — все. Токен бота агенту не передаётся. В песочнице передаётся только минимальный набор системных переменных и ключи агента.

### Проекты и команда {#env-team}

| Переменная | Описание |
|---|---|
| `PROJECTS_ROOT` | корень проектов: агент выбирает рабочую папку только внутри него. Без него — любая папка на машине |
| `USER_WORKSPACES` | `1` — личные пространства: у каждого сотрудника своя папка `<корень>/<Telegram ID>`. Нужен `PROJECTS_ROOT` |
| `AGENT_SANDBOX` | `bwrap` — песочница агента (только Linux, нужен пакет `bubblewrap`) |
| `ADMIN_SANDBOX` | `1` — песочнить также администратора в папках внутри `PROJECTS_ROOT` (только вместе с `AGENT_SANDBOX=bwrap`; по умолчанию выключено) |
| `SANDBOX_RO_PATHS` | дополнительные папки, которые песочница видит на чтение, через двоеточие |
| `BWRAP_COMMAND` | путь к `bwrap`, если его нет в `PATH` |
| `MAX_AGENTS` | сколько агентов сотрудников работает одновременно (по умолчанию 3) |
| `MAX_AGENTS_PER_USER` | сколько агентов одного сотрудника работает одновременно в разных темах (по умолчанию 2) |
| `ADMIN_MAX_AGENTS` | то же для администратора (по умолчанию 4) |
| `IDLE_MINUTES` | через сколько минут закрывается простаивающая сессия (по умолчанию 30) |

> Выбирайте `PROJECTS_ROOT` осознанно: не делайте корнем домашнюю папку или корень диска. Без `PROJECTS_ROOT` любой пользователь с доступом может выбрать проектом любую папку на машине — это режим для личной установки.

| `FILES_DIR` | каталог принятых и исходящих файлов (по умолчанию — папка данных бота) |
| `FILES_KEEP_DAYS` | сколько дней хранить такие файлы (по умолчанию 7) |
| `UPLOADS_QUOTA_MB` | квота каталога загрузок в МБ; `0` (по умолчанию) — без квоты |
| `TURN_IDLE_MINUTES` | завершать запрос, если агент не присылает обновлений дольше указанного числа минут; `0` (по умолчанию) — таймер выключен |
| `HISTORY_KEEP_DAYS` | удалять историю запросов и закрытых сессий старше указанного числа дней; `0` (по умолчанию) — не удалять |
| `LOGS_KEEP` | удалять архивы `data/debug.log.N` старше указанного числа дней; `0` (по умолчанию) — не удалять |
| `WIDGETS` | `1` — показывать `/model` и `/sessions` виджетами Telegram. По умолчанию выключено: Telegram пока не принимает виджеты от обычных ботов |
| `ANIMATED_ICONS` | `0` — обычные эмодзи вместо анимированных иконок в черновике |
| `ACPGRAM_DEBUG` | `1` — подробный журнал отправляемого в Telegram в `data/debug.log` |

## Безопасность {#security}

### Что видит и может агент {#security-agent}

- **Бот отвечает только тем, кому вы дали доступ.** Остальным он не отвечает.
- **Данные остаются у вас.** Код, настройки и история сессий лежат на машине с ботом, в локальной базе SQLite. Своих серверов у AcpGram нет. Сообщения проходят через Telegram, а запросы обрабатывает провайдер выбранного агента.
- **Без песочницы агент работает с правами учётной записи бота.** Рабочая папка проекта не запрещает ему читать и писать за её пределами, а файлы на диске, включая `.env` бота, он прочитать может. На Linux это закрывает [песочница](#sandbox), на любой системе — Docker.
- **Агент не получает токен бота**, а из ключей API — только ключи своего агента.
- **Текст агента не может нажать кнопку за вас.** Разметку кнопок строит бот; теги кнопок в тексте агента обезвреживаются.
- **Опасные сочетания бот называет сам.** Один раз он предупредит администратора в чате, если сотрудники работают без песочницы, администратор работает без неё в общей папке или `.env` доступен локальным группам пользователей Windows.
- **Папка данных защищена.** На Linux и macOS папка данных и база создаются с ограниченными правами; на Windows мастер убирает широкие права с `.env` и `data`.

### Секреты {#security-secrets}

- Пароли и ключи кладите в проект через [/files](#files-project): так они не попадают в запрос к модели.
- Файлы с секретами бот не отправляет в чат, не показывает в диффе и не включает в коммиты.
- Вход в Git хранится только у бота (см. [где хранится вход](#git-security)).
- Бесплатные модели могут использовать запросы для обучения: закрытый код и чувствительные данные в них лучше не отправлять.

### Проверяемые релизы {#security-releases}

Каждая версия AcpGram собирается из публичного кода в GitHub Actions и подписывается там же, а не загружается вручную.

- Пакет публикуется с npm provenance: блок «Provenance» на [странице пакета в npm](https://www.npmjs.com/package/acpgram) ведёт на конкретный коммит и файл сборки.
- Проверить после установки: `npm audit signatures`.
- Файлы релизов на GitHub подписаны Sigstore.
- Код проверяют CodeQL и OpenSSF Scorecard; у проекта есть бейдж [OpenSSF Best Practices](https://www.bestpractices.dev/projects/16722).

Как сообщить об уязвимости, описано в [политике безопасности](https://github.com/selesnow/acpgram/blob/main/SECURITY.md).

### Рекомендации {#security-tips}

- Запускайте бота под отдельной учётной записью, а не под своей основной.
- На общем сервере задайте `PROJECTS_ROOT`, включите личные пространства и песочницу, а на Linux при необходимости — `ADMIN_SANDBOX=1` для администратора.
- Уровень «Полный» выдавайте только тем, кому доверяете.
- На ключи API ставьте лимит расхода у провайдера.
- Обновляйтесь: в новых версиях выходят и исправления безопасности.

## Решение проблем {#troubleshooting}

### Где смотреть журнал {#logs}

Журнал службы — файл `data/service.log` в папке данных бота. На Linux его же показывает `journalctl --user -u acpgram -f`.

В Windows PowerShell 5.1 читайте журнал с указанием кодировки, иначе кириллица превратится в нечитаемые символы:

```powershell
Get-Content "$HOME\.acpgram\data\service.log" -Tail 30 -Encoding UTF8
```

Это путь для установки через npm. Если ставили установщиком, журнал лежит в `%LOCALAPPDATA%\acpgram\data\service.log`.

При запуске бот проверяет настройки. Если не задан токен или ID администратора, `PROJECTS_ROOT` указывает на несуществующую папку или не запускается агент по умолчанию, бот сразу завершается и пишет в журнал, что исправить.

### Windows: «выполнение сценариев отключено» {#powershell-scripts}

Команда `npm` или `acpgram` в PowerShell завершается ошибкой «Невозможно загрузить файл …
pm.ps1, так как выполнение сценариев отключено в этой системе» (в английской Windows — `running scripts is disabled on this system`). Чаще всего это случается при установке агента или самого AcpGram через npm.

PowerShell по умолчанию запрещает запуск сценариев, а `npm` и `acpgram` в нём запускаются как сценарии `npm.ps1` и `acpgram.ps1`. Разрешите сценарии для своей учётной записи (права администратора не нужны) и повторите команду:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Если менять настройку нельзя, добавляйте к командам `.cmd`: `npm.cmd install -g acpgram`, `acpgram.cmd setup`. Либо выполняйте их в классической командной строке (`cmd`): там этого запрета нет.

### Частые ситуации {#common-issues}

**Бот не отвечает.** Проверьте службу: `acpgram service status`, затем журнал. Убедитесь, что машина включена и не спит.

**Ошибка `Conflict` в журнале.** С одним токеном запущены два экземпляра бота, например старая служба и новая установка. Остановите лишний.

**У агента пометка «⚠️ нужен вход».** Агент запускается, но не авторизован. Войдите в него в терминале под той же учётной записью, под которой работает бот, либо добавьте ключ API в `.env`.

**Агент не находится под службой.** Под службой глобальные пакеты npm часто не в `PATH`. Запустите `acpgram setup` ещё раз (мастер запишет полные пути) либо укажите путь в `GEMINI_COMMAND`, `CLAUDE_COMMAND`, `CODEX_COMMAND`, `AGY_COMMAND` или `OPENCODE_COMMAND`.

**Служба на Windows не запускается.** Службе нужен пароль учётной записи, а не PIN-код Windows. Запустите `acpgram service install` из терминала администратора и введите пароль. Если NSSM не найден: установщик одной командой ставит его сам, а при установке через npm выполните `winget install --id NSSM.NSSM -e`. Для запуска в консоли NSSM не нужен.

**Новый ключ провайдера не добавил модели.** Перезапустите службу или откройте `/model`: бот обновит список моделей.

**Вместо анимированных иконок в черновике видны 🙂.** Клиент Telegram их не показывает. Задайте `ANIMATED_ICONS=0`.

**Команды Codex на Windows падают с `runner pipe-in`.** Режимам «Чтение» и «Обычный» нужна песочница Codex. Используйте уровень «Полный».

**Раздел `/git` отвечает, что недоступен.** На машине не найден `git`. Установите его или укажите путь в `GIT_COMMAND`.

**«Получить» сообщает, что изменения разные.** У вас и на сервере разошлись истории. Попросите агента объединить изменения и затем отправьте.

**Сервер не принял отправку.** На сервере есть более новые изменения. Сначала нажмите «Получить».

**Бот на Linux не запускается после включения песочницы.** Проверьте, что установлен `bubblewrap`. На Ubuntu 24.04 и новее может мешать AppArmor (см. [песочницу агента](#sandbox)).

**Сотрудник не видит агента в `/engine`.** Включите агента в карточке сотрудника в `/users`. В песочнице не предлагаются агенты, которые в ней не запустились.

**После обновления бот работает по-старому.** Служба продолжает выполнять прежнюю версию. Перезапустите её: `acpgram service restart`.
