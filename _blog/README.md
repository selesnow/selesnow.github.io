# Блог — как добавить статью

Блог собирается из Markdown-файлов в `_blog/posts/` скриптом `_build/blog.py` (его вызывает `_build/build.py`).
Готовые страницы лежат в `blog/` — **вручную их не правьте**, при следующей сборке изменения пропадут.

Достаточно положить файл в `_blog/posts/` и сделать `git push`: workflow `update-stats` (его триггер — пуш в `_blog/**`)
соберёт страницы, нарисует обложку, обновит `sitemap.xml` и закоммитит результат, после чего GitHub Pages выложит блог.
Локально то же самое делает `python _build/build.py` (или только блог: `python _build/blog.py`),
просмотр — `python -m http.server 8765` из корня репозитория → http://localhost:8765/blog/

## Файл статьи

Имя: `ГГГГ-ММ-ДД-короткое-имя.md` (латиницей, до ~80 знаков). Внутри — YAML-шапка и Markdown:

```markdown
---
title: Заголовок статьи
date: '2026-11-20'
slug: kratkiy-adres-stati
tags: [R, API]
categories: [R]
description: Одно-два предложения для карточки, поисковиков и соцсетей.
---

Текст статьи в Markdown…

## Заголовок раздела

Код с подсветкой:

```r
library(dplyr)
```
```

| поле | зачем |
|---|---|
| `title`, `date` | обязательные |
| `slug` | адрес `/blog/<slug>/`. Задайте явно и **потом не меняйте** — иначе сломаются ссылки. Нет поля — адрес получится транслитом заголовка |
| `tags`, `categories` | фильтры на главной блога. Берите уже существующие названия (R, API, Telegram, AI, Google Ads, Веб-аналитика…), иначе появится дубль |
| `description` | текст в карточке и в `<meta>`; нет поля — возьмётся начало статьи |
| `cover` | своя обложка `../images/имя.webp`; нет поля — возьмётся первая подходящая картинка из текста или нарисуется автоматически |
| `draft: true` | не публиковать (файл можно хранить в репозитории) |
| `archive_url`, `source_name` | для материалов, чей оригинал пропал: ссылка на снимок в Web Archive и название источника — на странице появятся плашка «из архива» и строка-источник |

Все теги стоит писать так же, как в уже опубликованных статьях (список — на странице `/blog/`, фильтр «Тег»).
Тема ИИ — тег `AI` (плюс, например, `ChatGPT`, `LLM`, `MCP`).

## Картинки

Положите файл в **`_blog/images/`** (PNG, JPG, GIF, SVG — любой размер) и сошлитесь на него в тексте:

```markdown
![описание картинки](../images/имя-файла.png)
```

При сборке PNG/JPG автоматически превращаются в WebP шириной до 1600 px и попадают в `blog/images/`
(ссылка в странице сама станет `.webp`, а у картинки появятся `width` и `height`). Имена — латиницей, без пробелов.
Исходные файлы остаются в `_blog/images/`, это нормально. Уже опубликованные картинки лежат в `blog/images/`.

## Обложки

Если в статье нет подходящей картинки (меньше 500×250 или слишком вытянутая), обложка рисуется по шаблону
`cover_tpl.html` через headless Chrome: иконка по тегу + ключевое слово, в стиле сайта. Файл — `blog/images/covers/<slug>.webp`.
Chrome нужен только для этого шага; без него карточка получит заглушку, а сборка не упадёт.

## Что ещё умеет Markdown здесь

* Видео и презентации: отдельной строкой `{{video: https://www.youtube.com/watch?v=ID}}` — подойдут YouTube, SlideShare (`.../embed_code/key/ID`), презентации Google Docs.
* Вопрос в интервью: `<p class="b-q">Текст вопроса</p>`.
* Заметка-плашка: `<div class="b-note"><i class="fa-solid fa-triangle-exclamation" aria-hidden="true"></i><div>Текст</div></div>`.
* Таблицы, нумерованные и маркированные списки, цитаты, ссылки (внешние откроются в новой вкладке, на `alexey-seleznev.pro` — в той же).
* Оглавление справа строится само, если в статье три и больше заголовков `##` / `###`.

## Остальное в папке

* `blog.css` — стили блога (копируются в `blog/blog.css` вместе с подсветкой кода Pygments).
* `cover_tpl.html` — шаблон обложек.
* `migration/` — одноразовые скрипты переноса блога с WordPress (экспорт, унификация тегов, оптимизация картинок, импорт двух интервью из Web Archive).
  Нужны только для истории: исходные данные (`raw/`, оригиналы картинок) в репозиторий не входят.
