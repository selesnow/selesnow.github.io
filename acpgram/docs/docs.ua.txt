# AcpGram documentation (ua)

## Що таке AcpGram {#intro}

AcpGram — міст між Telegram і кодинг-агентами. Він встановлюється на ваш комп’ютер або сервер і запускає там агента: Claude Code, OpenAI Codex, Gemini CLI, Antigravity CLI, OpenCode або Qwen Code. Ви пишете завдання боту в Telegram, агент читає файли, запускає команди й редагує код в обраному проєкті, а хід роботи, запити на підтвердження та результат надходять у чат.

AcpGram не замінює агента і сам нічого не «думає». Це пульт: один бот зі спільним інтерфейсом і командами, у якому ви перемикаєте агента, модель, проєкт і сесію.

Проєкт безкоштовний, з відкритим кодом (ліцензія MIT). Ви платите лише за самого агента — підписку або API його провайдера, як і під час роботи в терміналі. З OpenCode можна почати зовсім без оплати: у нього є безкоштовні моделі, яким не потрібен ключ.

#

Новинні канали в Telegram: [@acpgram](https://t.me/acpgram) (English), [@acpgram_ru](https://t.me/acpgram_ru) (русский), [@acpgram_ua](https://t.me/acpgram_ua) (українська).

### Як це влаштовано {#how-it-works}

1. **Telegram.** Ви пишете боту з телефона або комп’ютера.
2. **AcpGram.** Бот працює на вашій машині й сам підключається до Telegram. Публічна IP-адреса, відкриті порти та хмарний посередник не потрібні.
3. **Агент.** AcpGram запускає агента як підпроцес на тій самій машині та спілкується з ним за відкритим протоколом [Agent Client Protocol](https://agentclientprotocol.com) (ACP).

Агент працює там, де встановлено AcpGram. Поки ця машина вимкнена або спить, бот не відповість. Після перезавантаження служба запустить бота сама.

Щоб керувати кількома машинами, створіть окремого бота для кожної та встановіть AcpGram на кожній зі своїм токеном.

### Підтримувані агенти {#agents}

| Агент | Що потрібно на машині | Авторизація |
|---|---|---|
| Claude Code | Claude Code і міст `claude-agent-acp` | вхід в акаунт або `ANTHROPIC_API_KEY` |
| OpenAI Codex | Codex CLI і міст `codex-acp` | `codex login` або `OPENAI_API_KEY` |
| Gemini CLI | лише Gemini CLI | вхід в акаунт або `GEMINI_API_KEY` |
| Antigravity CLI | Antigravity CLI 1.5 або новіший | вхід через Google або ключ Gemini API |
| OpenCode | лише OpenCode | безкоштовні моделі без ключа або ключі провайдерів |
| Qwen Code | лише Qwen Code | OpenAI-сумісний API: OpenRouter, власний endpoint або ключі провайдера |

Достатньо одного агента. Решту можна підключити пізніше: AcpGram сам знаходить встановлених.

### Вимоги {#requirements}

- Windows, Linux або macOS. Перевірено на Windows Server і Linux (Ubuntu); на macOS використовується той самий код, що й на Linux.
- Node.js. Інсталятор однією командою сам встановить приватний Node.js 24, якщо відповідного немає. Для встановлення через npm потрібен Node.js 22.13 або новіший, для запуску з вихідного коду — Node.js 24.
- Для служби Windows — NSSM: інсталятор однією командою встановлює його сам без прав адміністратора; при встановленні через npm — `winget install --id NSSM.NSSM -e`. Для запуску в консолі NSSM не потрібен.
- Хоча б один агент із таблиці вище.
- Бот у Telegram і його токен від [@BotFather](https://t.me/BotFather).
- Для розділу Git — встановлений `git`. Для пісочниці на Linux — пакет `bubblewrap`.

У самого AcpGram немає залежностей npm.

## Встановлення {#install}

Зазвичай встановлення займає кілька хвилин. Якщо агент у вас уже працює в терміналі, знадобляться дві-три команди.

### Крок 1. Підготуйте агента {#install-agent}

Оберіть агента, яким користуєтеся. Команди `npm` потребують Node.js з npm. Якщо на Windows `npm` відповідає, що виконання сценаріїв вимкнено, див. [рішення](#powershell-scripts).

**OpenCode** — найпростіший старт: одразу працює на безкоштовних моделях, без ключів і акаунтів.

```sh
npm install -g opencode-ai
```

Цей крок можна пропустити: якщо на машині немає жодного агента, майстер налаштування AcpGram сам запропонує встановити OpenCode.

**Qwen Code.** Встановлюється через npm і підключається по ACP через OpenAI-сумісний API. Найпростіше почати з безкоштовних моделей OpenRouter: вкажіть `OPENROUTER_API_KEY` у `.env`, і AcpGram сам підготує налаштування Qwen.

```sh
npm install -g @qwen-code/qwen-code
```

За замовчуванням AcpGram використовує безкоштовні моделі OpenRouter: Nemotron 3.5 Lightning, Nemotron 3 Ultra 550B і ERNIE 5.5 Flash Preview. Власний список моделей можна задати в `QWEN_MODELS`, а інший OpenAI-сумісний endpoint — через `QWEN_BASE_URL`.

**Claude Code.** Потрібен сам Claude Code і міст, через який AcpGram з ним спілкується:

```sh
npm install -g @anthropic-ai/claude-code@latest
npm install -g @agentclientprotocol/claude-agent-acp
```

Запустіть `claude` і ввійдіть в акаунт або вкажіть ключ `ANTHROPIC_API_KEY` у майстрі AcpGram. На Windows стане в пригоді Git for Windows.

**OpenAI Codex.** Потрібен Codex CLI і міст:

```sh
npm install -g @openai/codex
npm install -g @agentclientprotocol/codex-acp
codex login
```

Замість `codex login` можна вказати `OPENAI_API_KEY`. На Windows режимам «Читання» і «Звичайний» потрібна робоча пісочниця Codex; якщо команди завершуються помилкою `runner pipe-in`, використовуйте рівень «Повний».

**Gemini CLI.** Міст не потрібен:

```sh
npm install -g @google/gemini-cli
```

Запустіть `gemini` й авторизуйтеся або вкажіть `GEMINI_API_KEY`.

**Antigravity CLI.** Потрібна версія 1.5 або новіша. Міст не потрібен, достатньо один раз увійти через Google:

```sh
agy acp --login
```

Замість входу можна працювати за ключем Gemini API: задайте `GEMINI_API_KEY` і додайте `"modelProvider": "gemini"` у `settings.json` Antigravity (`~/.gemini/antigravity-cli/settings.json`).

### Крок 2. Створіть бота в Telegram {#install-bot}

Відкрийте [@BotFather](https://t.me/BotFather), надішліть `/newbot` (або натисніть «Create a New Bot» у його вікні), придумайте ім’я та скопіюйте токен, який він надішле. Це займає хвилину.

Вмикати теми в `@BotFather` вручну не обов’язково: майстер налаштування і команда `/topics` уміють вмикати теми з бічною панеллю та забороняти додавання бота до груп самі (див. [режим «Діалоги»](#topics)).

### Крок 3. Встановіть AcpGram {#install-acpgram}

**Однією командою (рекомендовано).** Windows, у PowerShell:

```powershell
irm https://raw.githubusercontent.com/selesnow/acpgram/main/install.ps1 | iex
```

Linux і macOS, у терміналі:

```sh
curl -fsSL https://raw.githubusercontent.com/selesnow/acpgram/main/install.sh | bash
```

Інсталятор завантажує останній реліз із перевіркою контрольної суми в `%LOCALAPPDATA%\acpgram` (Windows) або `~/.local/share/acpgram` (Linux, macOS), за потреби встановлює приватний Node.js 24 і NSSM для служби Windows без прав адміністратора, додає команду `acpgram` у `PATH` і одразу запускає майстер налаштування.

**Через npm.** Якщо Node.js 22.13 або новіший уже встановлено:

```sh
npm install -g acpgram
acpgram setup
```

> На Windows NSSM потрібен лише для служби. Інсталятор однією командою встановлює його сам; `ACPGRAM_NO_NSSM=1` вимикає встановлення NSSM. При встановленні через npm: `winget install --id NSSM.NSSM -e`. Для запуску в консолі NSSM не потрібен.

> На Windows PowerShell може відповісти, що виконання сценаріїв вимкнено в цій системі, і не запустити `npm` або `acpgram`. Як це виправити однією командою: [Windows: «виконання сценаріїв вимкнено»](#powershell-scripts).

Налаштування (`.env`) і база (`data/bot.db`) за такого встановлення лежать у `~/.acpgram` (або в папці з `ACPGRAM_HOME`) і не втрачаються під час оновлення пакета.

### Крок 4. Майстер налаштування {#setup-wizard}

Майстер запускається сам після встановлення. Його можна запускати повторно командою `acpgram setup`: поточні значення підставляються.

1. **Токен бота.** Майстер одразу перевіряє його в Telegram і показує ім’я бота (якщо основне ім’я вимкнено, підхоплює додаткове активне ім’я).
2. **Налаштування бота в Telegram.** Якщо теми, бічна панель тем або заборона додавання до груп ще не задані, майстер запропонує застосувати рекомендовані налаштування в один крок — без `@BotFather`.
3. **Адміністратор.** Напишіть своєму боту будь-яке повідомлення — майстер сам визначить ваш Telegram ID. Можна ввести ID вручну.
4. **Корінь проєктів** — необов’язково. Якщо задати, майстер запитає і про [особисті простори](#workspaces).
5. **Пісочниця** — лише на Linux і лише якщо встановлено `bubblewrap` (див. [пісочницю агента](#sandbox)). Майстер також пропонує ввімкнути `ADMIN_SANDBOX=1`, щоб ізолювати агента адміністратора.
6. **Агенти.** Майстер знаходить встановлених агентів, записує їхні повні шляхи (щоб вони знаходилися й під службою) і пропонує обрати агента за замовчуванням. Якщо не встановлено жодного, пропонує одразу встановити OpenCode.
7. **Ключі API** — необов’язково. Токен, ключі й пароль вводяться приховано.
8. **Збереження.** Майстер записує `.env` (доступний лише власнику, з `GIT_AGENT_AUTH=1` за замовчуванням для нових установок), створює базу й надсилає вам тестове повідомлення в Telegram.
9. **Служба.** Майстер пропонує зареєструвати бота як службу, щоб він запускався разом із системою.

Після цього відкрийте бота в Telegram і надішліть `/start`.

### Служба й автозапуск {#service}

Служба запускає бота разом із системою і перезапускає в разі збою. Зазвичай її встановлює майстер, але нею можна керувати й вручну:

```sh
acpgram service install
acpgram service status
acpgram service restart
acpgram service stop
acpgram service uninstall
```

| ОС | Як працює служба |
|---|---|
| Windows | служба через [NSSM](https://nssm.cc): інсталятор AcpGram встановлює його сам, при встановленні через npm — `winget install --id NSSM.NSSM -e`; термінал від імені адміністратора |
| Linux | `systemd --user`; щоб бот працював без входу в систему, виконайте `sudo loginctl enable-linger $USER` |
| macOS | LaunchAgent (`launchd`) |

На Windows службі потрібен **пароль** вашого облікового запису: під ним авторизовано агентів. Якщо ви входите через обліковий запис Microsoft, це пароль від нього, а не PIN-код Windows. Обліковий запис без пароля запустити службу не може. Пароль не виводиться на екран і ботом не зберігається.

`acpgram service stop` зупиняє службу, не видаляючи її: після перезавантаження вона запуститься знову. Журнал служби — `data/service.log` у папці даних бота (на Linux ще й `journalctl --user -u acpgram -f`).

### Оновлення {#update}

Якщо встановлювали інсталятором:

```sh
acpgram update
acpgram service restart
```

Якщо через npm:

```sh
npm install -g acpgram@latest
acpgram service restart
```

Інсталятор і `acpgram update` завантажують останній публічний реліз GitHub, а не гілку `main`. Налаштування та історія сесій зберігаються.

### Docker {#docker}

В образі вже є всі шість агентів і мости: на хост нічого встановлювати не потрібно, майстер теж не потрібен. Знадобляться Git і Docker з Docker Compose.

```sh
git clone https://github.com/selesnow/acpgram.git
cd acpgram
cp .env.example .env
```

Заповніть у `.env` токен бота, свій Telegram ID, ключ агента й папку з проєктами. Наприклад, для Gemini CLI:

```sh
TELEGRAM_BOT_TOKEN=YOUR_BOT_TOKEN
ALLOWED_USER_ID=YOUR_TELEGRAM_ID
DEFAULT_ENGINE=gemini
GEMINI_API_KEY=YOUR_API_KEY
PROJECTS_DIR=./projects
```

```sh
docker compose up -d --build
docker compose logs -f
```

- `PROJECTS_DIR` — папка проєктів на хості. У контейнері вона стає `/projects`: це і є корінь для `/project`. Агент бачить лише її.
- Авторизація за ключами з `.env`: Gemini — `GEMINI_API_KEY`, Claude Code — `ANTHROPIC_API_KEY`, Codex — `OPENAI_API_KEY`. OpenCode працює і без ключа, на безкоштовних моделях.
- Antigravity CLI: після запуску один раз виконайте `docker compose exec -it bot agy acp --login` або працюйте за ключем Gemini API.
- Щоб зібрати легший образ, перелічіть потрібних агентів у `ENGINES` (`ENGINES=gemini claude`); `DEFAULT_ENGINE` має бути з-поміж зібраних.
- Бот у контейнері працює від користувача `node` (uid 1000). Щоб агент міг змінювати файли, папка проєктів має бути доступна цьому uid на запис: `sudo chown -R 1000:1000 <папка>`.
- Налаштування, входи та історія агентів зберігаються в томах і переживають оновлення контейнера. `docker compose down -v` їх видаляє.
- Потрібні R, Python або інші інструменти — зробіть свій `Dockerfile` поверх образу.

Docker чи встановлення напряму? Напряму агент отримує все, що встановлено на машині, і працює з правами облікового запису бота. У Docker він ізольований від системи й бачить лише папку проєктів, але й інструменти в нього лише ті, що є в образі. [Пісочниця агента](#sandbox) у Docker не підтримується.

### Запуск із вихідного коду {#from-source}

Потрібні Git і Node.js 24 або новіший.

```sh
git clone https://github.com/selesnow/acpgram.git
cd acpgram
npm run setup
```

Якщо відмовилися від служби, бот запускається командою `npm start`. Перший запуск без `.env` сам відкриє майстер налаштування. Можна обійтися й без майстра: скопіюйте `.env.example` у `.env`, заповніть і запустіть `npm start`.

### Перехід з інсталятора на npm {#migrate-npm}

Інсталятор на Windows додає в `PATH` папку `%LOCALAPPDATA%\acpgram\bin`. Якщо після цього встановити AcpGram через npm, Windows може й далі викликати стару версію.

1. Зупиніть і видаліть попередню службу: `acpgram service uninstall`. Інакше токен буде зайнятий, і Telegram поверне помилку `Conflict`.
2. Перевірте, яка команда викликається: `Get-Command acpgram`.
3. Приберіть стару папку з користувацького `PATH`:

```powershell
[Environment]::SetEnvironmentVariable("Path", (([Environment]::GetEnvironmentVariable("Path", "User") -split ';') | Where-Object { $_ -notlike '*\acpgram\bin' }) -join ';', "User")
```

4. Відкрийте нове вікно термінала й запустіть `acpgram setup`: майстер знайде попереднє встановлення і запропонує перенести `.env` і базу.

## Перші кроки в боті {#first-steps}

### Екран /start {#start-screen}

Команда `/start` показує, з чим ви зараз працюєте: агент, модель, рівень доступу і проєкт. Під повідомленням — кнопки основних дій, нижче — список команд.

Кнопки повторюють команди: проєкт, нова сесія, попередні сесії, агент, модель, завершення сесії, файли, Git, мова, режим діалогів. В адміністратора є ще співробітники, запрошення й активні сесії. Приховану клавіатуру можна повернути командою `/keyboard` (див. [меню кнопок](#reply-keyboard)).

### Меню кнопок і /keyboard {#reply-keyboard}

Команда `/start` один раз підключає клавіатуру з основними діями й запам’ятовує це. Повторні привітання та `/language` більше її не змінюють, тому меню не спливає щоразу, коли ви повертаєтеся в чат.

Якщо клавіатуру приховано або вона зникла, надішліть `/keyboard`. У режимі [«Діалоги»](#topics) вона підключається сама в кожній новій темі разом із привітанням.

Коли клавіатуру підключають, Telegram розгортає її в чаті. Приховати її можна штатною іконкою клавіатури в полі введення й відкрити звідти ж; окремої кнопки «Приховати меню» в боті немає. На деяких Android-клієнтах із темами клавіатура може показуватися лише всередині теми, а не в General: це обмеження клієнта, бот надсилає її коректно.

### Як поставити завдання {#first-task}

1. Оберіть проєкт: `/project` (див. [Проєкти](#projects)).
2. Напишіть завдання звичайним повідомленням, як колезі: «знайди, чому падає тест авторизації, і виправ».
3. Стежте за ходом роботи й відповідайте на запити дозволів кнопками.
4. Отримайте відповідь і, якщо потрібно, файли.

До повідомлення можна додати знімок екрана, документ або архів: підпис стає запитом (див. [Файли](#files)).

### Хід роботи й відповідь {#progress}

Поки агент працює, бот показує чернетку повідомлення:

- поки агент запускається — анімовані крапки Telegram;
- потім заголовок міркувань і хід роботи: останні п’ять кроків, лічильник решти та час виконання;
- якщо агент надіслав боту свій план — блок «План: 3/7» із пунктами (див. [План роботи](#plan));
- щойно пішла відповідь — останній крок і сам текст відповіді.

Підсумкова відповідь надходить із форматуванням: заголовки, списки, таблиці, блоки коду. Наприкінці — згорнутий блок «Хід роботи» з усіма кроками та підвал: агент, реальна модель, рівень міркувань, токени, вартість (у Claude Code і OpenCode), проєкт і час відповіді.

Якщо Telegram тимчасово не прийняв підсумок, бот повторить надсилання; якщо розмітка не пройшла — надішле звичайним текстом. Якщо бот перезапустився, поки агент працював, запит позначається перерваним: ви отримуєте зрозуміле повідомлення, а не тишу.

### План роботи {#plan}

Деякі агенти ведуть список справ і надсилають його боту. Тоді в чернетці з’являється блок «План: 3/7» із пунктами й позначками: ✅ зроблено, ▶️ виконується, ▫️ попереду. Блок видно, лише поки агент працює: коли надходить відповідь, він зникає разом із чернеткою.

Так буває не завжди, і залежить це від агента, а не від бота:

- **OpenCode** план боту не надсилає. Список справ він веде, але в ході роботи це має вигляд звичайного кроку «План роботи».
- **Claude Code і Codex** надсилати план уміють, але користуються цим не в кожному завданні: часто агент просто пише список текстом у відповіді.
- **Gemini CLI та Antigravity CLI:** показ плану не підтверджено.

Якщо блока «План» немає, план усе одно можна отримати: попросіть агента спочатку скласти список справ і позначати пункти в ході роботи. Він напише його текстом, як на знімку нижче.

**Режим планування Claude Code.** У Claude Code є власний режим планування: агент спочатку складає план, зберігає його у файл і просить схвалити. Бот показує цей запит із варіантами самого Claude Code (вони надходять англійською): схвалити й підтверджувати правки вручну, схвалити й працювати без підтверджень, схвалити й перейти в автоматичний режим або відхилити. Варіанти, які дали б агенту більше свободи, ніж дозволяє ваш рівень доступу, бот не показує.

У самому запиті тексту плану немає. Якщо хочете прочитати план до схвалення, попросіть агента спочатку надіслати його в чат.

### Запити дозволів {#permissions}

Коли агенту потрібен дозвіл на команду або редагування файлу, бот надсилає запит із кнопками:

- **«Дозволити»** — лише цю дію;
- **«Дозволити на цю сесію»** — цю й такі самі дії до кінця сесії;
- **«Відхилити»**.

Команда показується блоком коду, а в запиті на редагування файлу видно диф: що саме агент змінить, а не лише шлях. Довгі команди та багаторядкові дифи згортаються в розкривну цитату з попереднім переглядом початку, щоб кнопки рішення одразу залишалися на екрані.

Як працює «на цю сесію»:

- на кнопці написано, що саме буде дозволено;
- редагування файлів дозволяється повністю;
- команди — за назвою програми: дозволили `ls` — без запитань підуть усі `ls …`;
- у програм із підкомандами (`git`, `npm`, `docker` тощо) — за програмою і підкомандою: дозволили `git status` — підуть усі `git status …`, але не `git push`;
- оболонки (`bash -c`, `powershell`, `cmd /c`, `sudo`), інтерпретатори (`python`, `node`, `Rscript`, `npx`), команди з підстановками, записом у файл і змінними перед програмою дозволяються лише точно такі самі;
- у складеній команді мають бути дозволені всі частини.

Довга команда показується початком і кінцем із позначкою про обрізання; рядки журналу теж обрізаються.

Правило діє, поки працює процес агента: до `/new`, `/close`, закриття через простій або перезапуску бота. Варіанта «дозволити назавжди» в чаті немає.

Чи надходитимуть запити взагалі, залежить від [рівня доступу](#access-levels).

### Кнопки швидкої відповіді {#quick-replies}

Коли агент пропонує вибір («Який варіант застосувати?»), варіанти надходять кнопками прямо в його відповіді. Натискання надсилає текст варіанта агенту як ваше повідомлення.

### Повідомлення під час роботи {#queue}

Повідомлення, надіслане, поки агент виконує запит, не губиться. Бот ставить його в чергу й надішле агенту, щойно той закінчить. Під сповіщенням дві кнопки: «Зупинити й надіслати це» і «Не надсилати». У черзі одне повідомлення: нове замінює попереднє.

### Відповідь із цитатою {#quotes}

Дайте відповідь на повідомлення агента, виділивши в ньому фрагмент: агент отримає і ваш текст, і цей фрагмент. Зручно для прохань на кшталт «перепиши ось це».

### Зупинка запиту {#stop}

Команда `/stop` або кнопка зупинки під чернеткою перериває запит, що виконується, а якщо агент не відповів на скасування — завершує його процес. Сесія при цьому залишається: можна одразу написати наступне повідомлення.

Одруківка в команді (`/modle`) агенту не йде: бот запитає, чи не мали ви на увазі `/model`. На голосове, відео й стікер бот відповідає підказкою.

## Проєкти {#projects}

Проєкт — це папка, у якій працює агент. Вибір запам’ятовується для кожного користувача.

### Вибір проєкту {#project-select}

Команда `/project` показує папки кнопками. Угорі — останні проєкти, папками можна переходити, а потрібну обрати кнопкою «Обрати цю папку».

Швидше — вказати назву або шлях:

```text
/project landing
/project C:\my-app
/project ~/projects/web
```

Що доступно для вибору, залежить від налаштувань:

- без `PROJECTS_ROOT` (особисте встановлення) — будь-яка наявна папка, за замовчуванням домашня;
- з `PROJECTS_ROOT` — лише папки всередині кореня;
- з `PROJECTS_ROOT` і `USER_WORKSPACES=1` — у кожного співробітника своя папка всередині кореня (див. [особисті простори](#workspaces)).

### Новий проєкт {#project-new}

Кнопка «➕ Новий проєкт» у `/project` запитує назву, створює папку у відкритому місці й одразу робить її робочою. Невідповідну назву (шлях, службове ім’я, крапка на початку) бот попросить замінити. «Скасувати» або будь-яка команда скасовують очікування.

Адміністратору кнопка доступна всюди, співробітнику — в його особистому просторі.

### Проєкт із репозиторію {#project-clone}

Кнопка «⬇️ З Git» у `/project` показує ваші репозиторії на підключених сервісах списком із пошуком. Обраний репозиторій клонується й одразу стає проєктом. Спочатку потрібно підключити акаунт у `/git` (див. [Git](#git)).

## Сесії та діалоги {#sessions}

Сесія — це одна розмова з агентом: він пам’ятає все, про що йшлося.

### Нова сесія і повернення до попередньої {#sessions-resume}

- `/new` починає нову сесію: агент забуває попередню розмову.
- `/sessions` показує попередні сесії поточного проєкту: дата, агент, кількість запитів і початок першого запиту. Натискання відновлює сесію з того самого місця, навіть після перезапуску бота.

Сесія відновлюється в тому агенті, у якому була створена. Зміна агента командою `/engine` починає нову сесію.

### Режим «Діалоги»: теми Telegram {#topics}

Якщо боту ввімкнено теми в особистому чаті, кожна тема чату стає окремим діалогом з агентом: зі своїм проєктом, агентом та історією.

- Адміністратор може ввімкнути або вимкнути теми, бічну панель тем (зручний сайдбар зі списком діалогів), право користувачів створювати теми та заборону додавання бота до груп прямо в `/topics` або в майстрі `acpgram setup` — без `@BotFather`. У меню адміністратора `/topics` доступна завжди.
- Можна працювати в кількох темах одночасно.
- Повернувшись у тему пізніше, ви продовжуєте з того самого місця: сесія відновлюється сама.
- `/new` створює нову тему. Назву їй дає агент за першою відповіддю, з короткою назвою проєкту на початку.
- Агент може створити тему й сам на ваше прохання («створи окрему тему для …»): бот заведе тему з поточним проєктом, агентом і клавіатурою та надішле кнопку-посилання.
- Тема закріплена за своїм проєктом.
- General працює як звичайний діалог, а `/project` у ньому показує діалоги обраного проєкту кнопками. Якщо надіслати команду із загального списку чатів (коли Telegram сам заводить порожню тему), бот виконає її в General і видалить порожню тему.

Режим кожен обирає сам командою `/topics`: «Діалоги» або «Один чат».

Одночасно у співробітника працює до двох агентів, в адміністратора — до чотирьох (налаштування `MAX_AGENTS_PER_USER` і `ADMIN_MAX_AGENTS`). Якщо місця немає, вивантажується агент цього ж користувача, який простоює найдовше; його діалог продовжиться, коли ви до нього повернетеся.

### Закриття сесії {#sessions-close}

`/close` (або `/exit`) закриває сесію і вивантажує процес агента. Сесія, що простоює, закривається сама через 30 хвилин (`IDLE_MINUTES`). Закриту сесію можна відновити через `/sessions`.

## Агенти й моделі {#engines-models}

### Вибір агента {#engine}

В інтерфейсі бота агент називається «рушій»: кнопка «🤖 Рушій» і команда `/engine`.

Команда `/engine` показує агентів, доступних вам на цій машині. Вибір запам’ятовується для кожного користувача, зміна агента починає нову сесію.

```text
/engine claude
/engine opencode
```

Агенти, яких немає на сервері, не пропонуються. Агент, який запускається, але не авторизований (немає входу або ключа API), позначений «⚠️ потрібен вхід». Агент за замовчуванням задається налаштуванням `DEFAULT_ENGINE`.

### Вибір моделі {#model}

Команда `/model` показує моделі поточного агента (список надсилає сам агент) і рівень міркувань, де він є: у Claude Code й Antigravity CLI.

- За замовчуванням стоїть «Авто»: модель обирає сам агент.
- Вибір запам’ятовується окремо для кожного агента й застосовується з наступного запиту, без перезапуску сесії.
- Угорі екрана — кнопки з останніми обраними моделями.
- Найшвидший спосіб — пошук: `/model sonnet` покаже всі відповідні моделі кнопками.

### OpenCode і безкоштовні моделі {#opencode}

OpenCode бере моделі тих провайдерів, чиї ключі є в `.env` бота або підключені командою `opencode auth login`, плюс безкоштовні моделі, яким ключ не потрібен.

- Кожен ключ додає групу моделей у `/model`: Anthropic, OpenAI, Gemini, OpenRouter, Groq, DeepSeek, Mistral та інші провайдери OpenCode.
- OpenRouter дає сотні моделей різних розробників за одним ключем.
- Моделей багато, тому спочатку обирається група («🆓 Безкоштовні» або провайдер), а всередині неї моделі гортаються сторінками. В агрегаторів усередині групи є ще й розробники моделей.
- Моделі, які не вміють викликати інструменти (генерація зображень, музики), не показуються.
- Після додавання нового ключа список моделей оновлюється сам: під час перезапуску бота або наступного `/model`.

> Безкоштовні моделі можуть використовувати запити для навчання. Не надсилайте в них секрети й закритий код. Ключі та паролі передавайте проєкту через [/files](#files-project).

### Моделі Qwen Code {#qwen}

Qwen Code працює по ACP через OpenAI-сумісний API. AcpGram керує налаштуваннями Qwen в окремому Qwen home користувача і не потребує нативного Qwen OAuth.

- За замовчуванням AcpGram додає безкоштовні моделі OpenRouter: Nemotron 3.5 Lightning, Nemotron 3 Ultra 550B і ERNIE 5.5 Flash Preview.
- Для налаштування за замовчуванням вкажіть `OPENROUTER_API_KEY`, для іншого OpenAI-сумісного endpoint — `QWEN_BASE_URL`.
- Власний список моделей задається в `QWEN_MODELS` (`id|Назва;id|Назва`). Пріоритет: `QWEN_MODELS` > per-user `settings.json` > глобальний `~/.qwen/settings.json`/`QWEN_SETTINGS_FILE` > значення за замовчуванням.
- З безкоштовними моделями будьте обережні із секретами: провайдер може використовувати запити для навчання.

## Файли {#files}

### Файли для агента {#files-to-agent}

Фото або файл (текст, PDF, таблиця тощо, до 20 МБ) можна надіслати боту: підпис стає запитом. Файл зберігається на машині з ботом, агент отримує шлях до нього й читає його своїми інструментами. Зображення агент отримує ще й як картинку, якщо вміє з ними працювати.

- Альбом із кількох фото або файлів обробляється одним запитом.
- Архіви `.zip`, `.tar`, `.tar.gz`, `.tgz` бот розпаковує сам (не більше 500 файлів і 100 МБ) і передає агенту список файлів. `.7z` і `.rar` залишаються звичайним файлом.
- Надіслані файли зберігаються 7 днів (`FILES_KEEP_DAYS`).
- Завантаження обробляються по черзі: якщо агент зайнятий, зайвий файл видаляється, а ви отримуєте повідомлення «зайнято».
- Місце під завантаження можна обмежити налаштуванням `UPLOADS_QUOTA_MB`.

### Файли від агента {#files-from-agent}

Агент може створити файл і надіслати його в чат: звіт, таблицю, зображення, архів. Просто попросіть: «надішли результат файлом». Файл з’являється прямо у відповіді: JPEG і PNG — зображенням, решта — документом.

Вивід агента обмежено: один рядок виводу — до 32 МБ, підсумкова відповідь — додатково за розміром і кількістю кроків. Великі списки файлів читаються асинхронно й не блокують бота.

Надсилаються лише файли з папки проєкту та з каталогу вихідних файлів бота. Файли із секретами (`.env`, ключі, база й журнали бота, папка `.git`) у чат не надсилаються.

### Файли проєкту й секрети: /files {#files-project}

Усе, що ви пишете боту або надсилаєте йому файлом, іде агенту, а отже, у запит до моделі. Для паролів, токенів і ключів це не підходить. Команда `/files` кладе файл прямо в папку проєкту, оминаючи агента.

- **Список.** `/files` показує файли й папки поточного проєкту, разом із прихованими на кшталт `.env` (без `.git`, `node_modules` і посилань). Папками можна переходити кнопками, у файлу є картка з розміром і датою зміни.
- **«📝 Створити файл».** Бот запитує ім’я, можна з підпапкою: `config/.env`. Потім ви надсилаєте вміст одним повідомленням (до 3500 символів). Повідомлення з вмістом одразу видаляється з чату; у базу й журнали воно не пишеться.
- **«⬆️ Завантажити файл».** Наступний надісланий файл або альбом зберігається у відкриту папку проєкту під своїм іменем, а повідомлення з ним видаляється з чату. Очікування одноразове і спливає через 10 хвилин.
- **Видалення** — з картки файлу, з підтвердженням. Наявний файл замінюється лише після запитання «Замінити?».

Очікування вводу секрету зберігається в базі: після перезапуску бота старе повідомлення з токеном не буде прийнято — потрібно натиснути кнопку знову.

Без натискання кнопки все працює як раніше: файли й зображення, надіслані в чат, ідуть агенту.

На рівні «Читання» папки налаштувань агентів (`.claude`, `.gemini`, `.codex`, `.opencode`, `opencode.json`) у `/files` не показуються; звичайні файли, `.env` і клонування залишаються доступними як раніше.

Хто може змінювати файли: адміністратор; співробітник — у своєму особистому просторі, а в спільному корені — з рівнем «Звичайний» або «Повний». Переглядати список може будь-хто. Бот не пише й не видаляє за межами папки проєкту і не переходить за посиланнями.

> Що це дає і чого не дає. Секрет не потрапляє в запит до моделі від вас. Сам файл агенту доступний, інакше застосунки, які він пише й запускає, не змогли б ним користуватися. Бот регулярно нагадує агенту: файли із секретами не відкривати й не виводити, на налаштування посилатися за іменами, а по значення, якого бракує, відправляти вас у `/files`. Це вказівка, а не заборона: для особливо чутливих даних обирайте модель провайдера, який не навчається на запитах.

## Git: GitHub і GitLab {#git}

Команда `/git` пов’язує проєкти з GitHub, GitLab.com і своїми серверами GitLab та GitHub Enterprise. Підключити акаунт, клонувати репозиторій, переглянути зміни, надіслати код і відкрити запит на злиття можна кнопками, не відкриваючи термінал.

### Що потрібно {#git-requirements}

На машині з ботом має бути встановлений `git`. Це системна програма, а не залежність бота; без неї розділ відповідає, що недоступний. Якщо `git` не в `PATH`, вкажіть шлях у налаштуванні `GIT_COMMAND`.

### Вхід без токена {#git-signin}

GitHub і GitLab.com підключаються за посиланням і коротким кодом:

1. `/git` → «➕ Підключити GitHub» або «➕ Підключити GitLab.com».
2. Натисніть «🔗 Увійти без токена». Бот покаже посилання і код.
3. Відкрийте посилання, введіть код і підтвердьте доступ на сайті сервісу.
4. За кілька секунд бот сам напише, що акаунт підключено.

Створювати токен і надсилати щось секретне в чат не потрібно. Це працює в будь-якому встановленні без налаштування.

У GitLab такий вхід діє дві години, і бот сам продовжує його перед кожною операцією. Якщо сервіс перестав приймати вхід, акаунт відключається, і бот просить підключити його знову. У GitHub вхід безстроковий, доки ви не відключите акаунт або не відкличете доступ у налаштуваннях GitHub.

### Вхід за токеном доступу {#git-token}

Натисніть «➕ Підключити …»: бот дасть посилання на сторінку токенів сервісу і список потрібних прав. Створіть токен і надішліть його одним повідомленням.

- Повідомлення з токеном одразу видаляється з чату й агенту не передається.
- Бот перевіряє токен у сервісі, показує, хто підключений і до якого числа токен діє, і попереджає, якщо прав бракує.
- Потрібні права: у GitLab — `api`, `read_repository`, `write_repository` (без `api` не працюють публікація та запити на злиття), у GitHub — `repo`.
- За тиждень, за день і після завершення терміну дії токена бот напише власнику акаунта.
- Відключення акаунта в його картці видаляє токен із бота.

### Свої сервери {#git-servers}

GitLab і GitHub Enterprise вашої компанії додає адміністратор прямо в боті: `/git` → «⚙️ Свої сервери» → «➕ GitLab» або «➕ GitHub Enterprise» → адреса сервера, наприклад `https://git.example.com`.

Бот перевіряє, що за адресою відповідає сервер потрібного виду. Після цього кожен користувач може підключити на ньому свій акаунт токеном доступу. Там само сервер перейменовується і прибирається — разом із підключеними до нього акаунтами.

Вхід за посиланням і кодом працює лише для GitHub.com і GitLab.com. Свої сервери підключаються токеном.

### Клонування {#git-clone}

«⬇️ Клонувати репозиторій» (або «⬇️ З Git» у `/project`) показує ваші репозиторії кнопками: ті, що нещодавно змінювалися, — першими, з пошуком за назвою. Обраний клонується в особистий простір (без нього — поруч із поточним проєктом) і стає проєктом.

### Екран репозиторію {#git-repo}

Коли проєкт пов’язаний із репозиторієм, `/git` показує гілку, кількість змінених файлів, ненадісланих комітів і нових комітів на сервері. Під час відкриття і за кнопкою «Оновити» екран звіряється із сервером.

- **«⬇️ Отримати»** забирає зміни із сервера, якщо це можливо без злиття. Якщо історії розійшлися, попросіть агента об’єднати зміни («об’єднай зміни із сервера») і потім надішліть.
- **«⬆️ Надіслати»** надсилає готові коміти.
- **«💾 Зберегти й надіслати»** запитує опис, комітить усі зміни й надсилає.

Автор комітів — власник підключеного акаунта: його ім’я та пошта передаються і боту, і агенту, тож коміти агента підписані вами.

### Зміни й диф {#git-changes}

«📋 Зміни» відкриває список змінених файлів із позначками (новий, змінений, видалений, перейменований) і кількістю доданих і прибраних рядків. Натискання на файл показує, що в ньому змінилося: короткі зміни — прямо в повідомленні, середні й довгі (до 8000 символів) — згорнутим блоком коду в тому самому повідомленні, а зовсім великі — `.diff`-файлом.

Там само — коміти, які ще не надіслано, і ті, що чекають на сервері. Вміст файлів із секретами не показується. Усе це бот робить сам, без агента й без запитів до моделі.

### Гілки {#git-branches}

«🌿 Гілки» показує локальні гілки й гілки сервера одним списком. Натискання перемикає на гілку, «➕ Нова гілка» створює її від поточної.

- Якщо є незбережені зміни, бот не перемикає, а пропонує спочатку зберегти їх.
- Поки агент виконує запит, перемикання недоступне.
- Після перемикання наступний запит починає нову сесію агента: файли проєкту змінилися.
- «Надіслати» створює нову гілку й на сервері.

Переглядати зміни й гілки може будь-який користувач; перемикати і створювати гілки — той, кому дозволено змінювати файли проєкту.

### Скасування змін {#git-discard}

У картці зміненого файлу є «↩️ Повернути як було», на екрані «Зміни» — «↩️ Скасувати всі зміни». Змінені й видалені файли повертаються до останнього коміту, нові видаляються.

Дія незворотна, тому бот завжди просить підтвердження. Файли із секретами не зачіпаються.

### Публікація проєкту {#git-publish}

Для папки, яка ще не пов’язана із сервером, є «🚀 Опублікувати проєкт». Ви обираєте:

1. сервіс;
2. місце: особистий простір, групу GitLab (з підгрупами) або організацію GitHub — з пошуком за назвою;
3. видимість: закритий, внутрішній (у GitLab) або відкритий;
4. назву репозиторію.

Бот створює репозиторій, робить перший коміт без файлів із секретами й надсилає його.

### Запит на злиття {#git-mr}

«🔀 Запит на злиття» відкриває запит із поточної гілки в основну гілку репозиторію. Бот запитує заголовок (або пропонує опис останнього коміту), створює запит і надсилає посилання. Якщо відкритий запит із цієї гілки вже є, бот покаже його.

На основній гілці й за наявності ненадісланих комітів бот пояснить, що зробити спочатку.

### Коли надсилання пропонує агент {#git-agent}

Якщо в налаштуваннях задано `GIT_AGENT_AUTH=0`, в агента немає входу на сервер. Тоді прохання «закоміть і надішли» він виконує так: робить коміт, а під його відповіддю з’являється кнопка надсилання. Без вашого натискання на сервер нічого не йде.

### Де зберігається вхід і як запускається git {#git-security}

У режимі `GIT_AGENT_AUTH=0` вхід зберігається лише в базі бота. Клонування, отримання й надсилання виконує бот, а агент працює з репозиторієм локально: дивиться стан, порівнює, комітить, створює гілки, зливає.

- Вхід передається процесу `git` через оточення на час операції і лише для адрес свого сервісу. У налаштування репозиторію і в адресу він не записується.
- Бот запускає `git` із вимкненими хуками й помічниками входу, без загального і системного конфігу (на Linux і macOS), а з увімкненою пісочницею — усередині пісочниці того самого співробітника.
- Під час «Зберегти й надіслати» файли із секретами (`.env`, ключі, облікові дані) з коміту виключаються й дописуються в `.gitignore`. Якщо такий файл закомітив агент, перед надсиланням бот попереджає і чекає на «Надіслати все одно».

У нових установках майстер налаштування і `.env.example` за замовчуванням записують `GIT_AGENT_AUTH=1`: вхід передається і процесу агента, щоб він сам отримував і надсилав зміни без зайвих кнопок. Це зручніше, але токен при цьому видимий агенту й може потрапити в запит до моделі. Якщо ви не довіряєте моделям співробітників, задайте `GIT_AGENT_AUTH=0`.

### Обмеження {#git-limits}

- Підключаються лише репозиторії за HTTPS із підключених сервісів. Репозиторій з адресою SSH або з іншого сервера бот показує, але отримувати й надсилати в нього не може.
- Поки агент виконує запит, операції Git не запускаються.
- Налаштування самого репозиторію (фільтри) виконуються під час операцій: навмисно шкідливий агент міг би перехопити токен під час операції.

## Робота в команді {#team}

AcpGram можна встановити на спільний сервер і надати доступ колегам, зокрема тим, хто не працює в терміналі: усе керування відбувається з Telegram.

### Як додати людину {#team-invite}

За замовчуванням бот відповідає лише головному адміністратору (налаштування `ALLOWED_USER_ID`). Решту додають трьома способами:

- **Одноразове посилання.** `/invite` запитує рівень доступу й створює одноразове посилання, яке діє 24 години. Код `/start` спрацює одразу, навіть якщо запрошений щойно просто написав боту.
- **Запрошення з контактів (до 10 людей одразу).** Разом із посиланням `/invite` показує кнопку «👥 Запросити з контактів (до 10)» (`https://t.me/botinvite/<bot>`, працює для власника бота). Усіх, кого власник додасть протягом 15 хвилин, бот одразу підключає з обраним рівнем і вітає першим. Якщо запросити когось за цим посиланням напряму поза `/invite`, бот надішле адміністратору картку вибору рівня, не показуючи запрошеному «немає доступу».
- **Запит доступу.** Людина пише боту, адміністратор отримує окремий запит і схвалює або відхиляє його кнопками. Нові заявки від різних людей приходять незалежно; повторні повідомлення від однієї людини не завалюють чат — наступний запит можна надіслати через годину. Відхилених бот ігнорує.

Команда `/users` показує список співробітників. У картці співробітника: рівень доступу, доступні агенти й моделі, завершення сесії та відкликання доступу.

### Рівні доступу {#access-levels}

| Рівень | Що це означає |
|---|---|
| Читання | агент лише читає й аналізує, нічого не змінює |
| Звичайний | агент запитує дозвіл на редагування й команди; запити надходять самому співробітнику |
| Повний | агент працює з мінімумом підтверджень або зовсім без них (залежить від агента) |
| Адміністратор | повний доступ і керування співробітниками |

Кожен рівень відповідає своєму режиму в кожного агента:

| Рівень | Gemini CLI | Claude Code | Antigravity CLI | Codex | OpenCode | Qwen Code |
|---|---|---|---|---|---|
| Читання | `plan` | `plan` | `plan` | `read-only` | `plan` |
| Звичайний | `default` | `default` | `default` | `workspace-write` | `build` |
| Повний | `autoEdit` | `bypassPermissions` | `accept-edits` | `agent-full-access` | `build` |
| Адміністратор | `autoEdit` | `bypassPermissions` | `accept-edits` | `agent-full-access` | `build` |

На рівні «Повний» Gemini CLI й Antigravity CLI редагують файли без підтверджень, а команди виконують із підтвердженням; Claude Code працює взагалі без підтверджень. В OpenCode режимів два, а що агенту можна, визначає бот: «Читання» — редагування й команди заборонено, «Звичайний» — редагування, команди й завантаження сторінок із підтвердженням, «Повний» — усе без підтверджень.

Режим адміністратора можна змінити в `.env`: `ACP_MODE`, `CLAUDE_ADMIN_MODE`, `AGY_ADMIN_MODE`, `CODEX_ADMIN_MODE`, `OPENCODE_ADMIN_MODE`.

> Рівень «Повний» надавайте лише тим, кому довіряєте. Без [пісочниці](#sandbox) агент працює з правами облікового запису бота й може змінювати файли за межами проєкту.

### Агенти й моделі співробітника {#team-engines}

- **Агенти.** Новому співробітнику доступний лише агент за замовчуванням, решту адміністратор вмикає перемикачами в його картці. Агента за замовчуванням вимкнути не можна. Якщо забрати агента, у якому співробітник працює, його сесія закривається, і він переходить на агента за замовчуванням.
- **Моделі.** «🧠 Моделі співробітника» → агент → перемикачі моделей. За замовчуванням дозволено всі. За обмеження варіант «Авто» недоступний: співробітник працює в обраній дозволеній моделі або в першій із дозволених. Якщо агент фактично використав модель поза списком, запит зупиняється, а сесія закривається з зрозумілим повідомленням.
- Адміністратору доступні всі агенти й моделі.

### Активні сесії та ліміти {#team-limits}

Команда `/active` показує активні сесії та кнопки їх завершення.

- Одночасно працює не більше трьох агентів співробітників в усіх темах і агентах разом (`MAX_AGENTS`). Адміністратор у цей ліміт не входить.
- В одного співробітника — до двох агентів одночасно, в адміністратора — до чотирьох.
- Сесія закривається через 30 хвилин простою (`IDLE_MINUTES`).

### Витрати: /usage {#usage}

Команда `/usage` показує адміністратору запити, токени й вартість за кожним співробітником за 24 години, 7 і 30 днів.

### Особисті простори {#workspaces}

За замовчуванням усі співробітники працюють в одному корені проєктів. Особисті простори дають кожному свою папку:

```sh
PROJECTS_ROOT=/srv/projects
USER_WORKSPACES=1
```

Папка `<корінь>/<Telegram ID>` створюється сама під час першого звернення співробітника до бота.

- Співробітник обирає проєкти лише у своїй папці: чужі папки не показуються в `/project`, не знаходяться пошуком і не обираються шляхом. Піднятися вище своєї папки не можна.
- Шляхи він бачить від своєї папки («Мій простір», `site`, `site/landing`): розташування папок на сервері йому не показується.
- Кнопка «➕ Новий проєкт» створює папку в його просторі.
- Адміністратор бачить увесь корінь; особисті папки підписані іменами співробітників, а папку співробітника вказано в його картці в `/users`.
- Перед кожним запуском агента бот перевіряє, що папка проєкту існує і лежить у просторі співробітника.
- Папки співробітників бот не переносить і не видаляє, зокрема й у разі відкликання доступу.

Особисті простори обмежують вибір робочої папки в боті. Сам процес агента ізолює пісочниця.

### Пісочниця агента (Linux) {#sandbox}

Без пісочниці агент працює з правами облікового запису бота: робоча папка визначає, де він починає, але не забороняє читати й писати за її межами. Пісочниця закриває це питання.

```sh
sudo apt install bubblewrap
```

```sh
AGENT_SANDBOX=bwrap
```

Агент кожного співробітника запускається через [bubblewrap](https://github.com/containers/bubblewrap), системну утиліту Linux. Залежностей у бота не додається.

Усередині пісочниці агент бачить лише:

- на запис — папку проєктів співробітника, його окрему домашню папку й каталог вихідних файлів;
- на читання — його завантажені файли, систему (`/usr`, `/etc` тощо), Node.js і програми агента.

Налаштувань і бази бота, домашньої папки облікового запису бота, чужих папок і чужих процесів у пісочниці немає: на спробу прочитати чужий файл агент отримує «No such file or directory».

Що ще важливо:

- **У кожного свої налаштування агента.** Домашня папка у співробітника своя, тому історія сесій, налаштування і входи агентів у всіх окремі.
- **Агент має працювати без входу за підпискою.** Вхід, збережений у домашній папці облікового запису бота (`codex login`, вхід Google, підписка Claude), у пісочниці не видно. OpenCode на безкоштовних моделях працює взагалі без ключів, решта агентів — за ключем API з `.env`.
- **Рівень «Повний» стає безпечнішим.** Агент не запитує дозволів, але змінити може лише простір свого співробітника.
- **Адміністратор працює без пісочниці**, якщо не ввімкнено `ADMIN_SANDBOX=1`. З цим налаштуванням його агент також ізолюється в папках усередині `PROJECTS_ROOT`: співробітник не зможе залишити в спільній папці файл налаштувань агента, який виконається з правами бота. Бот один раз попереджає адміністратора в чаті, якщо пісочницю вимкнено, адміністратор працює без неї у спільній папці або `.env` доступний локальним групам користувачів Windows.
- **Перевірка під час запуску.** Бот перевіряє, що bubblewrap запускається, секрети бота зсередини не видно, а агенти в пісочниці стартують. Не працює пісочниця або агент за замовчуванням — бот не запускається і пише причину. Решта агентів, що не запустилися в пісочниці, співробітникам не пропонуються. Без `PROJECTS_ROOT` бот із `AGENT_SANDBOX=bwrap` не запускається; папки даних бота й інших співробітників до пісочниці не підключаються.
- **Агент встановлено в нестандартному місці** — додайте його папку в `SANDBOX_RO_PATHS`.
- **Сесії, розпочаті до ввімкнення пісочниці,** у ній не відновлюються.
- **Windows, macOS, Docker.** Пісочниці там немає. З налаштуванням `AGENT_SANDBOX` бот на Windows і macOS не запуститься, а не працюватиме мовчки без ізоляції.

Ubuntu 24.04 і новіші: простори імен користувача можуть бути закриті AppArmor. Якщо бот під час запуску повідомляє, що пісочниця не працює, виконайте:

```sh
sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
```

Щоб це діяло постійно, додайте це налаштування файлом у `/etc/sysctl.d/` або створіть профіль AppArmor для `bwrap`.

> Чого пісочниця не робить. Вона не обмежує мережу: агенту потрібен доступ до моделей, тому він дістається і до служб на самому сервері та в локальній мережі. Вона не ховає ключ API самого агента: він передається агенту в оточенні, тому ставте на ключ ліміт витрат у провайдера. І вона не обмежує диск, пам’ять і процесор.

## Мова інтерфейсу {#language}

Бот говорить російською, українською або англійською — відповідно до мови вашого Telegram. Для решти мов використовується `DEFAULT_LANG` (за замовчуванням англійська). Змінити мову можна командою `/language`: вибір важливіший за мову Telegram.

Команди `acpgram` у терміналі (майстер налаштування, служба, оновлення) говорять мовою системи: російська, українська, в інших випадках англійська. Мову можна задати налаштуванням `ACPGRAM_LANG`.

Повідомлення бота про помилки — перевірка агентів, тайм-аути, коди виходу Git, вхід за посиланням і кодом, пісочниця та помилки `acpgram` — також перекладаються на en, ru й uk.

## Налаштування: файл .env {#env}

Усі налаштування лежать у файлі `.env` у папці даних бота: `~/.acpgram` у разі встановлення через npm, `%LOCALAPPDATA%\acpgram` або `~/.local/share/acpgram` у разі встановлення інсталятором, корінь репозиторію в разі запуску з вихідного коду. Більшість значень записує майстер (`acpgram setup`). Після редагування файлу вручну перезапустіть службу: `acpgram service restart`.

Файл `.env` містить токен і ключі: не комітьте його й не пересилайте.

### Основні {#env-main}

| Змінна | Опис |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота. Обов’язкова |
| `ALLOWED_USER_ID` | числовий Telegram ID головного адміністратора. Обов’язкова |
| `DEFAULT_ENGINE` | агент за замовчуванням: `gemini`, `claude`, `agy`, `codex` або `opencode`. Якщо його не встановлено, бот не запускається |
| `DEFAULT_LANG` | мова бота, якщо мова Telegram користувача не російська, українська чи англійська: `en` (за замовчуванням), `ru` або `uk` |
| `ACPGRAM_LANG` | мова команд `acpgram` у терміналі: `ru`, `uk` або `en`. Зазвичай не потрібна: мова береться із системи |
| `ACPGRAM_HOME` | папка даних у разі встановлення через npm (за замовчуванням `~/.acpgram`) |
| `NSSM_PATH` | повний шлях до `nssm.exe` (лише Windows): потрібен для встановлення й перезапуску служби, якщо NSSM немає в `PATH`; інакше бот шукає приватний `bin\nssm.exe` і `PATH` |

| Змінна | Опис |
|---|---|
| `GEMINI_API_KEY` | ключ Gemini API. Не потрібен, якщо Gemini CLI вже авторизовано |
| `GOOGLE_API_KEY` | альтернативний ключ Google для моделей провайдера Google в OpenCode (замість `GEMINI_API_KEY`); бот передає його процесу OpenCode як `GOOGLE_GENERATIVE_AI_API_KEY` |
| `ANTHROPIC_API_KEY` | ключ Anthropic API для Claude Code (оплата за API, а не за підпискою) |

| `GEMINI_COMMAND` | повний шлях до Gemini CLI. Під службою глобальні пакети npm часто не в `PATH` |
| `CLAUDE_COMMAND` | команда моста Claude Code (за замовчуванням `claude-agent-acp`) |
| `CODEX_COMMAND` | повний шлях до моста Codex (за замовчуванням `codex-acp`) |
| `AGY_COMMAND` | повний шлях до Antigravity CLI (за замовчуванням `agy`) |
| `OPENCODE_COMMAND` | повний шлях до OpenCode (за замовчуванням `opencode`) |
| `QWEN_COMMAND` | повний шлях до Qwen Code (за замовчуванням `qwen`) |
| `QWEN_MODELS` | список моделей Qwen: `id|Назва;id|Назва`. За замовчуванням — безкоштовні моделі OpenRouter |
| `QWEN_BASE_URL` | базовий URL OpenAI-сумісного API для Qwen Code. Якщо не задано, а `OPENROUTER_API_KEY` є, AcpGram використовує OpenRouter |
| `QWEN_SETTINGS_FILE` | шлях до глобального `settings.json` Qwen для читання як резервного джерела моделей |
| `ACP_MODE`, `CLAUDE_ADMIN_MODE`, `AGY_ADMIN_MODE`, `CODEX_ADMIN_MODE`, `OPENCODE_ADMIN_MODE`, `QWEN_ADMIN_MODE` | режим кожного агента для адміністратора (див. [рівні доступу](#access-levels)) |
| `AGENT_ENV_HIDE`, `AGENT_ENV_PASS` | додаткові змінні оточення, які відповідно приховати від агента або передати йому (списки через кому) |
| `AGENT_START_TIMEOUT` | скільки секунд чекати запуску агента (за замовчуванням 120) |

Процес агента отримує з ключів API лише ключі свого агента: Claude Code — `ANTHROPIC_API_KEY`, Codex — `OPENAI_API_KEY`, Gemini CLI й Antigravity CLI — ключі Google, OpenCode — усі. Токен бота агенту не передається. У пісочниці передається лише мінімальний набір системних змінних і ключі агента.

### Проєкти й команда {#env-team}

| Змінна | Опис |
|---|---|
| `PROJECTS_ROOT` | корінь проєктів: агент обирає робочу папку лише всередині нього. Без нього — будь-яка папка на машині |
| `USER_WORKSPACES` | `1` — особисті простори: у кожного співробітника своя папка `<корінь>/<Telegram ID>`. Потрібен `PROJECTS_ROOT` |
| `AGENT_SANDBOX` | `bwrap` — пісочниця агента (лише Linux, потрібен пакет `bubblewrap`) |
| `ADMIN_SANDBOX` | `1` — пісочниця також для адміністратора в папках усередині `PROJECTS_ROOT` (лише разом із `AGENT_SANDBOX=bwrap`; за замовчуванням вимкнено) |
| `SANDBOX_RO_PATHS` | додаткові папки, які пісочниця бачить на читання, через двокрапку |
| `BWRAP_COMMAND` | шлях до `bwrap`, якщо його немає в `PATH` |
| `MAX_AGENTS` | скільки агентів співробітників працює одночасно (за замовчуванням 3) |
| `MAX_AGENTS_PER_USER` | скільки агентів одного співробітника працює одночасно в різних темах (за замовчуванням 2) |
| `ADMIN_MAX_AGENTS` | те саме для адміністратора (за замовчуванням 4) |
| `IDLE_MINUTES` | через скільки хвилин закривається сесія, що простоює (за замовчуванням 30) |

> Обирайте `PROJECTS_ROOT` свідомо: не робіть коренем домашню папку або корінь диска. Без `PROJECTS_ROOT` будь-який користувач із доступом може обрати проєктом будь-яку папку на машині — це режим для особистого встановлення.

## Безпека {#security}

### Що бачить і може агент {#security-agent}

- **Бот відповідає лише тим, кому ви надали доступ.** Решті він не відповідає.
- **Помилки не розкривають шлях сервера.** У повідомленнях шляхи маскуються, подробиці залишаються лише в журналі.
- **Часті повідомлення не заважають роботі.** Повторні повідомлення від незнайомців і сповіщення адміністратору приглушуються.
- **Дані залишаються у вас.** Код, налаштування та історія сесій лежать на машині з ботом, у локальній базі SQLite. Власних серверів в AcpGram немає. Повідомлення проходять через Telegram, а запити обробляє провайдер обраного агента.
- **Без пісочниці агент працює з правами облікового запису бота.** Робоча папка проєкту не забороняє йому читати й писати за її межами, а файли на диску, зокрема `.env` бота, він прочитати може. На Linux це закриває [пісочниця](#sandbox), на будь-якій системі — Docker.
- **Агент не отримує токен бота**, а з ключів API — лише ключі свого агента.
- **Текст агента не може натиснути кнопку за вас.** Розмітку кнопок будує бот; теги кнопок у тексті агента знешкоджуються.
- **Небезпечні поєднання бот називає сам.** Один раз він попередить адміністратора в чаті, якщо співробітники працюють без пісочниці, адміністратор працює без неї у спільній папці або `.env` доступний локальним групам користувачів Windows.
- **Папку даних захищено.** На Linux і macOS папка даних і база створюються з обмеженими правами; на Windows майстер прибирає широкі права з `.env` і `data`.

### Секрети {#security-secrets}

- Паролі й ключі кладіть у проєкт через [/files](#files-project): так вони не потрапляють у запит до моделі.
- Файли із секретами бот не надсилає в чат, не показує в дифі й не включає в коміти.
- Вхід у Git зберігається лише в бота (див. [де зберігається вхід](#git-security)).
- Безкоштовні моделі можуть використовувати запити для навчання: закритий код і чутливі дані в них краще не надсилати.

### Перевірювані релізи {#security-releases}

Кожна версія AcpGram збирається з публічного коду в GitHub Actions і підписується там само, а не завантажується вручну.

- Пакет публікується з npm provenance: блок «Provenance» на [сторінці пакета в npm](https://www.npmjs.com/package/acpgram) веде на конкретний коміт і файл збирання.
- Перевірити після встановлення: `npm audit signatures`.
- Файли релізів на GitHub підписано Sigstore.
- Код перевіряють CodeQL і OpenSSF Scorecard; у проєкту є бейдж [OpenSSF Best Practices](https://www.bestpractices.dev/projects/16722).

Як повідомити про вразливість, описано в [політиці безпеки](https://github.com/selesnow/acpgram/blob/main/SECURITY.md).

### Рекомендації {#security-tips}

- Запускайте бота під окремим обліковим записом, а не під своїм основним.
- На спільному сервері задайте `PROJECTS_ROOT`, увімкніть особисті простори й пісочницю, а на Linux за потреби — `ADMIN_SANDBOX=1` для адміністратора.
- Рівень «Повний» надавайте лише тим, кому довіряєте.
- На ключі API ставте ліміт витрат у провайдера.
- Оновлюйтеся: у нових версіях виходять і виправлення безпеки.

| `/active` | адміністратор | активні сесії та кнопки їх завершення |
| `/usage` | адміністратор | запити, токени й вартість за співробітниками за 24 години, 7 і 30 днів |

### Команди в терміналі {#commands-cli}

| Команда | Дія |
|---|---|
| `acpgram` | запустити бота в поточному терміналі |
| `acpgram setup` | майстер налаштування; можна запускати повторно |
| `acpgram update` | оновити до останнього релізу (для встановлення інсталятором) |
| `acpgram service install` | зареєструвати службу |
| `acpgram service status` | стан служби |
| `acpgram service restart` | перезапустити службу, наприклад після оновлення |
| `acpgram service stop` | зупинити службу, не видаляючи її |
| `acpgram service uninstall` | видалити службу |

## Розв’язання проблем {#troubleshooting}

### Де дивитися журнал {#logs}

Журнал служби — файл `data/service.log` у папці даних бота. На Linux його ж показує `journalctl --user -u acpgram -f`.

У Windows PowerShell 5.1 читайте журнал із зазначенням кодування, інакше кирилиця перетвориться на нечитабельні символи:

```powershell
Get-Content "$HOME\.acpgram\data\service.log" -Tail 30 -Encoding UTF8
```

Це шлях для встановлення через npm. Якщо встановлювали інсталятором, журнал лежить у `%LOCALAPPDATA%\acpgram\data\service.log`.

Під час запуску бот перевіряє налаштування. Якщо не задано токен або ID адміністратора, `PROJECTS_ROOT` вказує на папку, якої не існує, або не запускається агент за замовчуванням, бот одразу завершує роботу й пише в журнал, що виправити.

### Windows: «виконання сценаріїв вимкнено» {#powershell-scripts}

Команда `npm` або `acpgram` у PowerShell завершується помилкою «Не вдається завантажити файл …\npm.ps1, оскільки виконання сценаріїв вимкнено в цій системі» (в англійській Windows — `running scripts is disabled on this system`). Найчастіше це стається під час встановлення агента або самого AcpGram через npm.

PowerShell типово забороняє запуск сценаріїв, а `npm` і `acpgram` у ньому запускаються як сценарії `npm.ps1` і `acpgram.ps1`. Дозвольте сценарії для свого облікового запису (права адміністратора не потрібні) і повторіть команду:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Якщо змінювати налаштування не можна, додавайте до команд `.cmd`: `npm.cmd install -g acpgram`, `acpgram.cmd setup`. Або виконуйте їх у класичному командному рядку (`cmd`): там цієї заборони немає.

### Часті ситуації {#common-issues}

**Бот не відповідає.** Перевірте службу: `acpgram service status`, потім журнал. Переконайтеся, що машина ввімкнена й не спить.

**Помилка `Conflict` у журналі.** З одним токеном запущено два екземпляри бота, наприклад стара служба й нове встановлення. Зупиніть зайвий.

**В агента позначка «⚠️ потрібен вхід».** Агент запускається, але не авторизований. Увійдіть у нього в терміналі під тим самим обліковим записом, під яким працює бот, або додайте ключ API в `.env`.

**Агент не знаходиться під службою.** Під службою глобальні пакети npm часто не в `PATH`. Запустіть `acpgram setup` ще раз (майстер запише повні шляхи) або вкажіть шлях у `GEMINI_COMMAND`, `CLAUDE_COMMAND`, `CODEX_COMMAND`, `AGY_COMMAND` чи `OPENCODE_COMMAND`.

**Служба на Windows не запускається.** Службі потрібен пароль облікового запису, а не PIN-код Windows. Запустіть `acpgram service install` із термінала адміністратора і введіть пароль. Якщо NSSM не знайдено: інсталятор однією командою встановлює його сам, а при встановленні через npm виконайте `winget install --id NSSM.NSSM -e`. Якщо утиліта лежить у нестандартному місці, задайте `NSSM_PATH`. Для запуску в консолі NSSM не потрібен.

**Новий ключ провайдера не додав моделі.** Перезапустіть службу або відкрийте `/model`: бот оновить список моделей.

**Замість анімованих іконок у чернетці видно 🙂.** Клієнт Telegram їх не показує. Задайте `ANIMATED_ICONS=0`.

**Команди Codex на Windows завершуються помилкою `runner pipe-in`.** Режимам «Читання» і «Звичайний» потрібна пісочниця Codex. Використовуйте рівень «Повний».

**Розділ `/git` відповідає, що недоступний.** На машині не знайдено `git`. Встановіть його або вкажіть шлях у `GIT_COMMAND`.

**«Отримати» повідомляє, що зміни різні.** У вас і на сервері розійшлися історії. Попросіть агента об’єднати зміни і потім надішліть.

**Сервер не прийняв надсилання.** На сервері є новіші зміни. Спочатку натисніть «Отримати».

**Бот на Linux не запускається після ввімкнення пісочниці.** Перевірте, що встановлено `bubblewrap`. На Ubuntu 24.04 і новіших може заважати AppArmor (див. [пісочницю агента](#sandbox)).

**Співробітник не бачить агента в `/engine`.** Увімкніть агента в картці співробітника в `/users`. У пісочниці не пропонуються агенти, які в ній не запустилися.

**Після оновлення бот працює по-старому.** Служба й далі виконує попередню версію. Перезапустіть її: `acpgram service restart`.

Створіть issue на [GitHub](https://github.com/selesnow/acpgram/issues): вкажіть операційну систему, версію AcpGram, агента і кроки відтворення. Токени й ключі API не додавайте.
