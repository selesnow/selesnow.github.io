# Материалы внутренних страниц

Страницы `opensource/`, `courses/`, `videos/`, `talks/`, `articles/`, `interviews/` собираются скриптом `_build/build.py` из JSON
в `_build/data/`. Если править их HTML, изменения пропадут при следующей сборке (она идёт и ночью). Поэтому любое изменение
контента = правка JSON + пересборка. Свои заметки — это не сюда, а в блог (скилл `blog-post`); раздел «Статьи» только для **внешних** публикаций.

## Куда что идёт

| Что добавляем | Файл | Как устроена запись |
|---|---|---|
| Внешняя статья | `articles.json` (список) | `i` (сквозной номер: возьми максимальный + 1), `title`, `src` (источник), `y`, `m`, `url`, `img`, `desc` (строки, один язык), `via` (`""` или `"archive"`), `topics` |
| Доклад / вебинар | `talks.json` (список) | `date` (`ГГГГ-ММ`), `event`, `cat` (`conference` или `webinar`), `kind`, `title`, `desc` (трёхъязычные объекты), `yt` (ID ролика YouTube), опционально `url`, `photo` |
| Видеоурок | `videos.json` → `lessons` | `yt`, `date`, `topic`, `title`, `desc` (трёхъязычные); циклы уроков — в `series` |
| Интервью, опрос, комментарий | `interviews.json` (список) | `date`, `outlet`, `url`, `img`, `kind` (`interview`, `survey`, `comment`), `title`, `desc`, опционально `quote`, `via`, `internal` |
| Курс | `courses.json` | сложная запись (`program`, `stats`, `audience`): смотри соседние курсы; курс «R для маркетинга» — отдельный генератор `rcourse_page.py` |
| Пакет | `packages.json` | `name`, `cat`, `icon`, `since`, `cran`, `docs`, `tagline`, `desc`; архивные: `"archived": true` |

Допустимые значения `topics`, `topic`, `kind`, `level`, `cat` не выдумывай: они заданы константами в `_build/build.py`
(`TOPICS`, `SOURCES`, `VIDEO_TOPICS`, `KINDS`, `LEVELS`, `PKG_CATS`). Незнакомый ключ приведёт к ошибке сборки.
Новый вид тега/источника = правка шаблона, а не только данных, поэтому сперва скажи об этом пользователю.

## Порядок

1. `git pull --rebase --autostash` (см. `CLAUDE.md`: ночной workflow постоянно меняет `master`).
2. **Посмотри 2–3 соседние записи** нужного файла и скопируй их форму: так не промахнёшься с полями и стилем описаний.
3. **Текст.** Если запись трёхъязычная, нужны все три языка (`ru`, `ua`, `en`), украинский и английский — полноценные, не заглушки. Описание — 1–2 предложения.
   Не добавляй в описания пакетов причины архивации: на сайте их быть не должно.
4. **Ссылки.**
   - Курсы и документацию пакетов давай через `https://alexey-seleznev.pro/...`, не `selesnow.github.io`.
   - Внешнюю ссылку проверь, что она открывается (python `urllib`, а не curl: у curl на этой машине проблемы с проверкой отзыва сертификатов).
     Часть сайтов блокирует ботов (403) — это не значит, что страница мертва, но и подтвердить её нельзя: скажи об этом пользователю.
   - Оригинал пропал — ссылка на снимок Web Archive: `https://web.archive.org/web/<дата>/<исходный URL>` и `"via": "archive"`.
     Наличие снимка проверяй API `https://archive.org/wayback/available?url=…&timestamp=ГГГГММ` (прямые запросы к web.archive.org
     с этой машины блокируются как бот-трафик). Нет снимка — не публикуй мёртвую ссылку, сообщи пользователю.
   - Ссылки на старый WordPress-блог не добавляй: его материалы живут в `/blog/`.
5. **Правь JSON точечно через Edit, не перегенерируй файл целиком.** Форматирование у файлов разное: `articles.json` — ровно `indent=1`
   с `ensure_ascii=False`, а в `talks.json` и некоторых других несколько полей стоят на одной строке. Любая перегенерация скриптом
   перетряхнёт весь файл, и `git diff` перестанет показывать, что именно добавилось. Копируй вид соседней записи, кириллицу оставляй как есть.
   После правки проверь, что файл валиден:
   `python -c "import json;json.load(open('_build/data/talks.json',encoding='utf-8'))"`.
6. **Пересобери**: `python _build/build.py` (нужен Node.js). Посмотри `git diff --stat`: изменились должны нужный JSON, его страница,
   возможно `assets/tailwind.css`/счётчики и sitemap. Если поехали десятки посторонних страниц — разберись почему, прежде чем коммитить.
7. **Проверь глазами** скилом `site-check`: карточка появилась, фильтры и счётчики в шапке раздела обновились, картинка загрузилась.
8. Коммит и пуш — только по просьбе пользователя (скилл `publish`).

## Чего не делать

- Не правь `*/index.html` вручную (кроме лендинга `index.html`, который, наоборот, правится только руками и только по просьбе).
- Не добавляй `ads/` в навигацию и sitemap: страница открывается лишь по прямой ссылке.
- Не удаляй старые записи, чтобы «навести порядок», без просьбы: карточки влияют на счётчики в шапках разделов.
- Не клади в карточки незапрошенные цитаты и награды: только то, что подтверждено источником.
