# Добавление материала в блог

Блог собирается из Markdown в `_blog/posts/` скриптом `_build/blog.py` (его вызывает `_build/build.py`).
Страницы в `blog/` генерируются — **руками не правь**. Полная справка — `_blog/README.md`, читай её, если нужен нестандартный случай
(архивные материалы, обложки, плашки).

## Порядок работы

1. **`git pull`** (при незакоммиченных изменениях — `git pull --rebase --autostash`): ночной workflow коммитит в `master`.
2. **Узнай у пользователя недостающее**, если его нет в запросе: текст статьи, заголовок, дату (по умолчанию сегодня),
   картинки, видео. Заголовок, `description` и теги можно предложить самому, но покажи их пользователю.
3. **Создай файл** `_blog/posts/ГГГГ-ММ-ДД-короткое-имя.md`: латиница, без пробелов, до ~80 знаков
   (длинные кириллические имена ломают клонирование на Linux).
4. **Заполни шапку** (см. ниже), затем текст.
5. **Картинки** положи в `_blog/images/` (латиница, без пробелов), в тексте: `![описание](../images/имя.png)`.
   Сборка сама сделает WebP в `blog/images/`.
6. **Проверь локально**: `python _build/blog.py`, затем `python -m http.server 8765` из корня и http://localhost:8765/blog/.
   Убедись, что статья открывается, код подсвечен, картинки и видео на месте, карточка в списке выглядит нормально.
   Не забудь остановить сервер после проверки.
7. **Коммит и пуш — только по просьбе пользователя.** Коммитить можно сам файл статьи и картинки из `_blog/images/`
   (после пуша workflow `update-stats` сам соберёт страницы, обложку и `sitemap.xml`). Если собирал локально,
   в коммит попадут и сгенерированные файлы — это нормально. Не коммить `_blog_export/` (исключён из git).

## Шапка статьи

```yaml
---
title: Заголовок статьи
date: '2026-11-20'
slug: kratkiy-adres-stati
tags: [R, API]
categories: [R]
description: Одно-два предложения для карточки, поисковиков и соцсетей.
---
```

| Поле | Правило |
|---|---|
| `title`, `date` | обязательные; если в заголовке двоеточие или кавычки — бери его в одинарные кавычки |
| `slug` | адрес `/blog/<slug>/`: латиница через дефис, задай явно. **После публикации не меняй никогда** |
| `tags`, `categories` | только из уже существующих (список ниже), иначе появятся дубли в фильтрах |
| `description` | 1–2 предложения, до ~200 знаков; нет поля — возьмётся начало статьи |
| `cover` | своя обложка `../images/имя.webp`; нет поля — первая подходящая картинка или автогенерация |
| `draft: true` | не публиковать (файл остаётся в репозитории) |
| `archive_url`, `source_name` | только для материалов, чей оригинал пропал (плашка «из архива») |

Тема ИИ — тег `AI` (плюс `ChatGPT`, `LLM`, `MCP` и т. п.). Актуальный список тегов и рубрик (его не выдумывай, возьми из статей):

```
python -c "import yaml,glob,collections as C; t=C.Counter(); k=C.Counter()
for f in glob.glob('_blog/posts/*.md'):
    d=yaml.safe_load(open(f,encoding='utf-8').read().split('---')[1]); t.update(d.get('tags') or []); k.update(d.get('categories') or [])
print('categories:',k.most_common()); print('tags:',t.most_common())"
```

(на Windows добавь `PYTHONUTF8=1`, иначе кириллица в консоли ломается).

## Что умеет Markdown в блоге

- Код с подсветкой: тройные кавычки с языком (` ```r `).
- Видео и презентации: отдельной строкой `{{video: https://www.youtube.com/watch?v=ID}}` (YouTube, SlideShare `.../embed_code/key/ID`, Google Docs).
- Вопрос в интервью: `<p class="b-q">Текст вопроса</p>`.
- Плашка-заметка: `<div class="b-note"><i class="fa-solid fa-triangle-exclamation" aria-hidden="true"></i><div>Текст</div></div>`.
- Таблицы, списки, цитаты, ссылки (внешние открываются в новой вкладке, на `alexey-seleznev.pro` — в той же).
- Оглавление справа строится само при трёх и более заголовках `##`/`###`. Внутри статьи начинай с `##`, `#` не нужен: `title` уже заголовок.
- Ссылки на свои курсы и пакеты — через домен `https://alexey-seleznev.pro/...`, не `selesnow.github.io`.

## Чего не делать

- Не правь `blog/*/index.html` и `sitemap.xml` (блок `/blog/` обновляется сборкой).
- Не меняй `slug` у опубликованных статей и не переименовывай их файлы без необходимости.
- Не добавляй ссылки на старый WordPress-блог — материалы живут в `/blog/`.
- Не коммить и не пушь без просьбы пользователя.
