# Новая страница сайта

Страница сайта состоит не из одного файла: её адрес нужно прописать в нескольких местах, и пропуск любого даёт тихую поломку
(нет стилей, нет в меню, не попала в коммит ночной сборки, нет в поиске). Поэтому проходи чек-лист целиком.

Сначала выясни у пользователя: **адрес** (`/slug/`), **название на трёх языках**, **иконка** Font Awesome, нужно ли **меню** (общая шапка
и футер) или это скрытая страница, как `ads/` (на неё ссылок нет, в sitemap не добавлять), и **откуда данные** (JSON или Markdown).
Лендинг `index.html` правится только руками и только по просьбе, поэтому добавлять ли пункт в его меню, спроси отдельно.

## Чек-лист для страницы в общем меню

1. **Генератор** `_build/build.py`: функция `build_<slug>()` по образцу ближайшей страницы (`build_interviews` — самый короткий пример):
   `head('<slug>', 'Название | Алексей Селезнёв', 'description')` → `nav('<slug>')` → `hero(...)` → контент → `cta_block() + footer() + tail()`,
   страницу сохрани вызовом `write('<slug>', page)` (он кладёт её в `<slug>/index.html`). Если нужен список карточек в JSON-LD,
   передай `jsonld=page_jsonld(slug, name, description, items)`. Вызови её в блоке `if __name__ == '__main__':` в нужном порядке.
2. **`PAGES`** (рядом с `build.py:69`): кортеж `(slug, иконка, (ru, ua, en))`. Отсюда берутся пункты шапки и колонка «Сайт» футера.
3. **`PAGE_BLURBS`**: подпись страницы для списка на 404 — `KeyError` на сборке, если забыть.
4. **Данные**: JSON в `_build/data/<slug>.json` с трёхъязычными полями (`T(ru, ua, en)` и `tr({...})`). Весь видимый текст на трёх языках.
5. **Фото в шапке (необязательно)**: исходник в `img/`, сжатая копия WebP в `assets/photos/`, запись в `PHOTOS` (`src`, `w`, `h`, `pos`, `event`, `year`,
   при желании `side='left'`) и `photo='<slug>'` в вызове `hero(...)`. Фото выбирай неиспользованное, чтобы разделы не повторялись.
6. **Tailwind**: добавь страницу в `content` файла `_build/tailwind.config.js` (`./<slug>/index.html`), иначе у новых классов не будет стилей.
7. **Workflow** `.github/workflows/update-stats.yml`: допиши каталог `<slug>` в строку `git add ...` шага Commit changes,
   иначе ночная сборка не закоммитит страницу, и она будет «откатываться» к устаревшей версии.
8. **Sitemap**: блок `<url>` с `<loc>`, `<lastmod>`, `<changefreq>`, `<priority>` по образцу соседей, адреса на домене `https://alexey-seleznev.pro/`.
9. **Футер лендинга**: после изменения `PAGES` замени блок `<!-- FOOTER -->`…`</footer>` в `index.html` выводом
   `python -c "import sys; sys.path.insert(0,'_build'); import build; print(build.footer(''))"`. Больше в лендинге ничего не трогай.
10. **schema.org и аналитика**: `head()` сам добавляет JSON-LD `CollectionPage` и GA4 (`GA_ID`). Проверь, что в `<head>` страницы они есть. Новые ссылки,
    уходящие наружу, снабжай `data-ga-event="content_outbound_click"` по образцу карточек.
11. **Сборка и проверка**: `python _build/build.py` (нужен Node.js), затем скилл `site-check` (1440 и 1920 px, меню не должно «разъезжаться»,
    адрес из sitemap должен отдавать 200 после выкладки).

## Скрытая страница (как `ads/`)

Пункты 1, 4, 6, 7 и сборка из чек-листа выше; **не** добавляй в `PAGES`, `PAGE_BLURBS`, sitemap и футер. Ссылок на неё с сайта быть не должно.

## Что учесть

- Новые Tailwind-классы в шаблонах требуют пересборки (`build.py` делает её сам): без неё классы не работают.
- Не правь сгенерированные `*/index.html` вручную.
- Коммит и пуш — только по просьбе пользователя (скилл `publish`).
